Everything Parsing · Module 21 · Part III — Top-Down Parsing

Nullable & FIRST Sets

Module 20 used FIRST and nullable as if computing them were obvious. They're not — the definitions are circular. FIRST(E) depends on FIRST(T) depends on FIRST(F) which, through F → ( E ), depends back on FIRST(E). You break the circle with a least fixed point: start from nothing, apply the rules until a full pass changes nothing, and the answer you land on is the smallest one consistent with the grammar.

The payoff

Watch it converge. For X → Y, Y → Z, Z → z | ε: nullable is {} → {Z} → {Y,Z} → {X,Y,Z} → {X,Y,Z}. Each round peels one layer; the repeat with no change is the proof you're done.

01

The Big Analogy — rumours through an office

A fact gets out. On Monday, only the people who witnessed it know (that's Z → ε — directly nullable). On Tuesday, everyone who talks to a Monday-knower knows (Y → Z, so Y inherits it). On Wednesday, their contacts know (X → Y). Each day the circle of knowers grows by exactly one hop. Eventually a day passes where nobody new finds out — the rumour has saturated the office. That day is your signal to stop.

That's a fixed-point iteration. "Who knows the rumour" only ever grows, it can't grow past the whole office, so it must settle. And it settles on the smallest set that's closed under "if you talk to a knower, you know" — nobody is in it who wasn't reachable from an actual witness. That smallest closed set is the least fixed point, and it's the honest answer: it doesn't credit anyone with knowledge they have no path to.

nullable is "who can derive the empty string." FIRST is "which terminals can show up first" — same office, same rumour dynamics, just a richer fact travelling.

02

What Happens, Step by Step

nullable

  1. Start N = {}.
  2. Pass over every production A → X₁…Xₖ. If A ∉ N and every Xᵢ ∈ N (vacuously true for an empty rhs), add A to N.
  3. If the pass added anything, go again. Otherwise stop — N is nullable.

FIRST

  1. Start FIRST(A) = {} for every nonterminal.
  2. Pass over every production A → X₁…Xₖ. Walk the rhs left to right:
    • Xᵢ a terminal → add Xᵢ to FIRST(A), stop walking this rhs.
    • Xᵢ a nonterminal → add FIRST(Xᵢ) \ {ε}; if Xᵢ is nullable, continue to Xᵢ₊₁, else stop.
    • walked off the end (all nullable) → add ε to FIRST(A).
  3. If the pass changed any set, go again. Otherwise stop.

nullable is computed first and used as a fixed input to the FIRST pass — that keeps FIRST a single monotone iteration instead of two intertwined ones.

The state, drawn

nullable, layer by layer — indirect.grammar

  X -> Y      Y -> Z      Z -> z | epsilon

  round 0:  { }                         nothing assumed
  round 1:  { Z }                        Z -> epsilon  fires
  round 2:  { Y, Z }                     Y -> Z, and Z is now nullable
  round 3:  { X, Y, Z }                  X -> Y, and Y is now nullable
  round 4:  { X, Y, Z }                  no change  -> STOP

FIRST waiting on a chain — expr.grammar

  E -> T Ep     T -> F Tp     F -> ( E ) | num | id

  round 0:  FIRST(E)={}  FIRST(T)={}  FIRST(F)={}
  round 1:  FIRST(E)={}  FIRST(T)={}  FIRST(F)={ ( id num }    F's terminals land
  round 2:  FIRST(E)={}  FIRST(T)={ ( id num }                 T <- F
  round 3:  FIRST(E)={ ( id num }                              E <- T
  round 4:  no change  -> STOP

  FIRST(E) is genuinely empty for two rounds. It has nothing wrong with it —
  the information just hasn't arrived through the E <- T <- F chain yet.

FIRST past a nullable prefix — cascade.grammar

  S -> A B C d      A -> a|epsilon    B -> b|epsilon    C -> c|epsilon

  walking S's rhs:  A (nullable) add {a}, continue
                    B (nullable) add {b}, continue
                    C (nullable) add {c}, continue
                    d (terminal) add {d}, STOP
  FIRST(S) = { a b c d }        epsilon NOT included: 'd' is not nullable
04

The Code, Explained

nullable — the whole loop

FIRST of a sequence — stop at the first non-nullable symbol

Why it always terminates — the two-line proof

Monotone: every line of the loop only ever calls add. No element is ever removed. Bounded: nullable can't exceed the finite set of nonterminals; each FIRST(A) can't exceed the finite set of terminals plus {ε}. A sequence that only grows and can't grow forever must stabilise. The number of rounds is at most the number of nonterminals plus one.

Least, not just any

The grammar's equations can have many solutions. For A → A, both FIRST(A) = {} and FIRST(A) = {x} satisfy "FIRST(A) ⊇ FIRST(A)." Only the empty one is correct — no string is actually derivable from A. Starting from {} and adding only what a rule forces guarantees you land on the least fixed point: every element in it traces back to a real terminal in a real production. A larger fixed point would be a parser that expects tokens the grammar can't actually produce there.

Getting a blank or broken result?

A → ε doesn't mark A nullable — an empty rhs must make the "all symbols nullable" test vacuously true.
Indirect nullability missed — you ran one pass, not to convergence.
FIRST stops too early — keep adding FIRST(Xᵢ₊₁) while Xᵢ is nullable.
ε in FIRST(S) when S isn't nullable — only add ε if the whole rhs is nullable.

07

Brain Exercise

(1) Grammar S → A a, A → B C, B → b | ε, C → c | ε. Run the nullable iteration by hand. Is A nullable? Is S? (2) Compute FIRST(S). Why isn't a alone the answer?

Answers

(1) round 1: B, C (both have an ε production). round 2: A — A → B C and both are now nullable. round 3: no change. A is nullable; S is not — S → A a has the terminal a.

(2) Walk S's rhs A a: A is nullable, so add FIRST(A) \ {ε}. FIRST(A): walk B C — B nullable, add {b}; C nullable, add {c}; off the end, add ε → {b, c, ε}. So from A we contribute {b, c}. Then A nullable, continue to a (terminal) → add {a}, stop. FIRST(S) = {a, b, c}. a alone is wrong because A can vanish, exposing whatever A itself could start with.

08

There Are No Dumb Questions

Why compute nullable separately instead of folding it into FIRST?

You could — ε ∈ FIRST(A) is "A is nullable." Computing nullable first, as its own fixed point, makes the FIRST pass a single clean monotone iteration with nullable as a constant input, instead of two mutually-recursive iterations. Same answer, easier to reason about and to trace.

How many rounds does it take?

At most (number of nonterminals + 1). Each productive round adds at least one element along a dependency chain no longer than the nonterminal count; the final round is the confirming pass that adds nothing. Real grammars converge in a handful of rounds regardless.

What's a "fixed point" in one sentence?

A value the function maps to itself: apply the rules to it and you get the same value back. Here: run one more pass over the productions and no set changes.

Could the iteration land on the wrong fixed point?

Not if you start from empty and only add. That path always reaches the least fixed point, which is the correct one — it contains exactly the terminals/nullability that some real derivation justifies. Starting from a non-empty guess could overshoot.

Does a left-recursive grammar break this?

No — FIRST and nullable are computed fine for any grammar, left recursion included (FIRST(A) for A → A x just contributes nothing new on the self-reference). Left recursion breaks parsing (Module 19) and LL(1)-ness (Module 20), not these sets.

What's Next

Module 22 — FOLLOW Sets does the other half. FOLLOW takes FIRST as an input and runs its own least-fixed-point iteration: for every B → α A β, whatever can start β can follow A, and if β is nullable, whatever follows B follows A too. Plus the $ end-marker, which turns out not to be optional. With FIRST and FOLLOW both in hand, Module 25 assembles the LL(1) parsing table.
