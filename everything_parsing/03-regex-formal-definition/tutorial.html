Everything Parsing · Module 03 · Part I — Foundations

Regular Expressions,Formally

A regular expression is not a string of magic punctuation. It is a tree with exactly six kinds of node — three base cases, three operators — and a precedence, exactly like arithmetic. This module parses one into that tree and shows each node is a single operation from Module 2.

The one comparison that unlocks it

a|bc* parses as a | (b·(c*)) — the same way 2 + 3 · 4² groups as 2 + (3·(4²)). Star is the exponent, concatenation is the product, | is the sum. Learn that table and every regex parses itself.

01

The Big Analogy — regex is arithmetic with letters

You already parse expressions in your head. Nobody reads 2 + 3 × 4 as (2 + 3) × 4. There is a precedence table — exponent, then times, then plus — and it decides the shape without any parentheses.

A regular expression is the same object with the operators renamed:

ArithmeticRegexMeansBinds…
x² (exponent)x* (star)zero or more copiestightest
x · y (times)xy (juxtaposition)x then ymiddle
x + y (plus)x|y (alternation)x or yloosest

So ab*|c is (a · (b*)) + c — you would never read the arithmetic version as ((a·b)²) or a·(b² + c), and you shouldn't read the regex that way either. Parentheses in a regex do the exact job they do in arithmetic: override the table.

The base cases are the "numbers": a single character a, the empty string ε (like 0 under +, or 1 under ·), and the empty language ∅ (the regex that matches nothing at all).

02

What Happens, Step by Step

  1. Desugar as we parse. r+ → Concat(r, Star(r)). r? → Union(r, Epsilon). These never become their own node kind.
  2. Parse by precedence, one method per level:
    • regex = concat ('|' concat)* — split on | last
    • concat = repeat* — juxtaposition; zero items means ε
    • repeat = atom ('*'|'+'|'?')* — postfix quantifiers
    • atom = '(' regex ')' | CHAR — a character, or a parenthesised sub-regex
  3. The result is a tree of Empty, Epsilon, Char, Union, Concat, Star.
  4. Meaning, option A — toLanguage(maxLen): walk the tree; each node calls one Module-2 operation. Bounded because star is.
  5. Meaning, option B — matches(w): exact, no bound. Compute the set of leftover suffixes after matching a prefix; w matches iff "" is a possible leftover.
03

The state, drawn

How a|bc* becomes a tree

  input:  a | b c *

  regex ─┬─ concat ── repeat ── atom ─ 'a'
         │
         ├─ '|'
         │
         └─ concat ─┬─ repeat ── atom ─ 'b'
                    └─ repeat ─┬─ atom ─ 'c'
                               └─ '*'  → Star

  tree:   (alt  a  (cat  b  (star c)))
                │        │        │
                │        │        └── * bound c, tightest
                │        └── concatenation joined b and (c*)
                └── | joined a and everything to its right, loosest

Each node kind → one Module-2 operation

NodetoLanguage does
EmptyLanguage.EMPTY  (∅)
EpsilonLanguage.EPSILON  ({ε})
Char cLanguage.of("c")
Union(l,r)l.toLanguage().union(r.toLanguage())
Concat(l,r)l.toLanguage().concat(r.toLanguage())
Star(x)x.toLanguage().star(maxLen)

Exact matching: the leftover-suffix set for (a|b)*abb on "aabb"

  leftovers( (a|b)*abb , "aabb" )
    (a|b)* can consume ""      → leftover "aabb"   then abb needs 'a''b''b' from "aabb" → fails (…"bb" then "b")
    (a|b)* can consume "a"     → leftover "abb"    then abb: 'a''b''b' from "abb"       → leftover ""   ✓
    (a|b)* can consume "aa"    → leftover "bb"     then abb needs 'a' from "bb"          → fails
  "" is in the leftover set  →  MATCH
04

The Code, Explained

Precedence is which method calls which

repeat (star) is the innermost call, so * binds tightest. regex (union) is the outermost, so | binds loosest. The grammar's call structure is the precedence table — a fact Module 20 will make fully general.

The whole semantics, six lines

Language toLanguage(int maxLen) {
  if (this instanceof Empty)     return Language.EMPTY;
  if (this instanceof Epsilon)   return Language.EPSILON;
  if (this instanceof Char ch)   return Language.of(String.valueOf(ch.c));
  if (this instanceof Union u)   return u.l.toLanguage(maxLen).union(u.r.toLanguage(maxLen)).truncate(maxLen);
  if (this instanceof Concat co) return co.l.toLanguage(maxLen).concat(co.r.toLanguage(maxLen)).truncate(maxLen);
  if (this instanceof Star s)    return s.x.toLanguage(maxLen).star(maxLen);
}
Crazy detail — the one guard that keeps (a*)* from hanging

Exact matching walks the tree computing "leftover suffixes." For Star, it tries matching the inner regex once and recursing on what's left. But the inner regex of (a*)* can match zero characters — leaving the string unchanged — so the recursion would call itself on the same input forever. The fix is one line: if (!rest.equals(w)) — a repetition must consume at least one character to count. It's sound because "zero repetitions" is already handled by the out.add(w) above it. See DECISIONS.md — this one is bucket (a), forced.

05

Limits — what this module cannot do yet

Can't do yet

  • Match efficiently. matches is exponential on adversarial input — no automaton yet (Modules 10–13).
  • Character classes, ranges, ., escapes — parsed as literal characters only. (They're all unions; the tutorial lists the desugarings.)
  • Anchors (^ $), capture groups, backreferences.
  • Say whether two regexes are equivalent, except by comparing bounded enumerations (Module 14 does it exactly).
  • Compile to a state machine — that's the entire point of Part II.

Can do

  • Parse any regex over the six core constructs into an unambiguous tree, honouring * > concat > |.
  • Desugar + and ? and prove they add nothing.
  • Turn the tree into a bounded Language with a six-case recursion.
  • Decide matches(w) exactly and terminating, for every regex including (a*)*.
  • Reject malformed input with a position: (, *a, a).

Getting a blank or broken result?

unexpected '|' at position 0 — the fixture line had no  |  separator (space on both sides), so the tests were parsed as part of the regex.
'*' has nothing to apply to — a regex starting with a quantifier. They're postfix; put an atom to the left.
A match you expect fails — read the tree: line. ab* is a(b*), not (ab)*. Add parentheses.
matches hangs — you dropped the rest != w guard in the Star case.

07

Brain Exercise

The parser turns concat with zero items into an Epsilon node. So () parses, and a()b parses.

(1) What tree does a()b produce, and what language does it denote? Is it the same language as ab?

(2) The empty language ∅ has a node kind (Empty) but no syntax — there's no character you can type to get one. Why is Empty in the AST at all? Where would a real regex tool produce an Empty node?

Answers

(1) a()b → (cat (cat a eps) b). toLanguage: {a} · {ε} · {b} = {a} · {b} = {ab}. Same language as ab, different tree. {ε} is the identity for concatenation (Module 2), so an Epsilon node anywhere in a Concat chain is invisible to the meaning — it just makes the tree taller. (This is exactly why real regex engines fold ε away during compilation.)

(2) Empty is the identity for union and the annihilator for concatenation — you need it to state algebraic laws and to have a total set of node kinds. A real tool produces it when simplifying: the derivative of a non-matching character (d/da of b is ∅), intersection of disjoint regexes, or subtracting a language from itself. Module 13's subset construction leans on "this state accepts ∅" — the dead state.

08

There Are No Dumb Questions

Why is ab a Concat node? I don't see an operator.

Concatenation in regex is juxtaposition — writing two things next to each other. The operator is invisible, exactly like 3x means 3 · x in algebra. The parser's concat() method loops "as long as the next thing isn't |, ), or end, glue on another repeat."

My regex library has \d, [a-f], ., lazy *?, lookahead… where are those?

The first three are pure sugar over union: \d = 0|1|…|9, [a-f] = a|b|c|d|e|f, . = union of every symbol in Σ. Lazy quantifiers and lookahead are matching-strategy features — they don't change which language is described, only which match a backtracking engine reports first. Backreferences (\1) are the real outlier: they describe non-regular languages, so an engine that has them isn't a regular-expression engine in the formal sense.

You said "regex = arithmetic." Does that mean a(b|c) distributes to ab|ac?

Yes — concatenation distributes over union, just like multiplication over addition: a(b|c) = ab|ac and (a|b)c = ac|bc. Both denote the same language (check with toLanguage). The trees differ; the meanings don't. Regex algebra has a full set of such laws, and minimising a regex (or its automaton, Module 14) is applying them.

Why build toLanguage AND matches? Isn't one enough?

They answer different questions. toLanguage(n) shows the structure — "a regex is those three Module-2 operations" — but only up to length n. matches(w) is the real yes/no you want for one string, exact and unbounded. Neither is how a production engine works (that's an automaton), but together they pin down the meaning with no hand-waving.

Is this parser "recursive descent"? I thought that was later.

It is, and it is. Module 19 is where recursive descent gets its formal treatment — the rule "one function per nonterminal," the conditions under which it works without backtracking, the failure modes. You've now written the pattern three times (M1, M4, here) precisely so that by M19 it's familiar and the module can focus on why it works rather than how to type it.

What's Next

You have a regex as a tree and two ways to give it meaning, neither of them fast. Module 4 — Context-Free Grammars: Formal Definition (already built) generalises the notation: a grammar has named rules that can refer to each other and to themselves, which lets it describe languages no regex can — like aⁿbⁿ. Then Part II comes back to this regex tree and compiles it, node by node, into a finite-state machine that matches in a single left-to-right pass (Modules 9–16). The Star node you built here is where the loops in that machine come from.
