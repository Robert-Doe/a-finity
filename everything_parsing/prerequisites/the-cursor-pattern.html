The Cursor Pattern

Every scanner, every parser, every table-driven engine in this course reads its input through the same four-or-five-method object: an array plus an integer that only moves forward (mostly).

01

The shape

A cursor wraps a sequence items and an index pos (starts at 0). Its whole interface:

  1. peek() — return items[pos] without moving. At or past the end, return a designated end value ('\0', EOF, null).
  2. peek(k) — look k ahead: items[pos+k]. k=1 is "the token after next."
  3. advance() — return items[pos], then pos++. (Consume one.)
  4. eof() — pos >= items.length.
  5. mark() / reset(m) — save pos, later restore it. Only parsers that backtrack (PEG, Appendix) need these.

Optional sugar: match(x) = "if peek()==x, advance() and return true; else false." expect(x) = "match(x) or throw a syntax error."

A cursor is a finger under a line of text. peek is looking at the word your finger is under. advance is sliding the finger one word right. eof is your finger falling off the end of the line.

A plain recursive-descent parser is a reader who never moves the finger backward. A backtracking parser is a reader who sometimes says "wait, let me re-read that bit" — that is mark / reset.

02

Both languages, same object

The only real difference: Java's char is a UTF-16 code unit and there is a true "not a character" value ('\0'); JS has no char type, so a one-character string "\0" stands in. Module 36 in the Appendix is where that difference stops being cosmetic.

03

The rule that keeps it honest

One invariant

Every path through a parse function consumes at least one token, or reports an error. A function that can return having consumed nothing, inside a loop, is an infinite loop waiting for the right input. Module 16 (left-recursion removal) is entirely about restoring this invariant to grammars that violate it.
