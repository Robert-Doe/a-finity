Big-O Quick Reference

Four complexities carry the whole course, plus one idea — amortised — that trips people up. Everything else is detail.

01

The four that matter

ClassMeansIn this course
O(1)constant — independent of input sizeone table lookup in an LL/LR parser; advance, retract
O(n)linear — one passa DFA scan; recursive descent; LL(1) and LR(1) parsing of the whole input

The entire reason Parts III–IV exist: parsing by generating the language is O(2ⁿ); a real parser is O(n). Same answer, unrecognisably different cost.

02

Amortised O(1)

"Amortised O(1)" means: any single operation might be expensive, but any long run of them averages to O(1) each.

Module 9's buffer: most advance() calls just do forward++ (O(1)). Once every halfSize characters, one advance() also triggers a buffer load (O(halfSize)). Spread that load's cost over the halfSize cheap calls that follow and each advance() is O(1) on average — even though individual calls aren't.

Same reasoning: a dynamic array's append is amortised O(1) despite the occasional O(n) resize; a packrat parser's memoised rule is amortised O(1) despite the first call doing real work.

03

What we ignore

Constant factors, cache behaviour, and the difference between O(n) and O(n log n) — all real, all beyond this course's scope. When a module says "linear," it means "one pass over the input, no nested re-scanning," and that is the property that matters for a parser.
