Induction & Recursion

A recursive function and an inductive proof are the same shape: handle the base case, then handle a step assuming the smaller cases already work. Half this course is one or the other.

01

Structural recursion

A function is structurally recursive over a tree if every recursive call is on a strictly smaller subtree. Then it always terminates — the tree is finite, so the calls bottom out at leaves.

Result walk(Node n) {
  if (n is a leaf) return base(n);           // base case
  return combine(n, walk(n.left), walk(n.right)); // step: children first
}

Module 3's regex evaluator, Module 5's tree walk, Module 12's Thompson construction — all this shape.

02

Structural induction

To prove a property P holds for every tree:

  1. Base case: prove P(leaf) for each kind of leaf.
  2. Inductive step: for each internal node kind, prove P(node) assuming P already holds for each child (the "inductive hypothesis").

Since every tree is built from leaves by finitely many node applications, the two cases together cover all trees.

Example — the Thompson bound (Module 12)

P(r): "the NFA for a regex r with k nodes has ≤ 2k states."
Base: a Char has 1 node, 2 states. 2 ≤ 2·1. ✓
Step (Concat): l has a nodes (≤ 2a states by hypothesis), r has b (≤ 2b). Concat adds 1 node, 0 states. New: 1+a+b nodes, ≤ 2a+2b states, and 2a+2b ≤ 2(1+a+b). ✓
Step (Star): 1 new node, 2 new states: ≤ 2a + 2 = 2(a+1). ✓

03

Induction on a number / a string length

Same idea, "smaller" = "fewer": prove P(0), then P(n) assuming P(n-1). Or, for strings, induct on the length. The pumping-lemma arguments (Module 7) and the fixed-point computations (FIRST/FOLLOW, Module 17) both rely on this.

04

The one thing that goes wrong

Non-well-founded recursion

If a recursive call is not on something strictly smaller, the function may not terminate and the induction is invalid. A grammar rule A → A b (left recursion) turns a "structural" descent into an infinite one — that's why Module 16 exists. A PEG rule that can match the empty string inside a * loops similarly — hence the "consumed ≥ 1" guards you'll see.
