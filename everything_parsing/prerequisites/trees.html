Trees

Parsing produces trees; every parser in this course walks one. The vocabulary is small and you only need it precise, not deep.

01

The words

  • Node — one item. Carries a value (a grammar symbol, a regex operator, a token) and an ordered list of child nodes.
  • Root — the one node with no parent. A tree has exactly one.
  • Leaf — a node with no children. In a parse tree, leaves are terminals; internal nodes are nonterminals.
  • Child order matters. Concat(a, b) ≠ Concat(b, a). These are ordered trees, unlike a generic graph.
  • Subtree — any node plus all its descendants. Recursion over trees is "do something with this node, then recurse into each child's subtree."
  • Depth — edges from the root. Height — longest root-to-leaf path.
02

Two traversals you will write constantly

            (cat)
           /     \
         a       (star)
                   |
                   b

  pre-order   (visit node, THEN children):   cat, a, star, b
  post-order  (children, THEN visit node):   a, b, star, cat

Pre-order is how you print or serialise a tree — you emit the operator before its operands. Post-order is how you evaluate one — a node's meaning is computed from its childrens' already-computed meanings. Module 3's toLanguage is a post-order walk: Star can't produce its language until b has produced its.

03

Recursion over a tree — the shape

Result walk(Node n) {
  if (n is a leaf)   return baseCaseFor(n);
  Result a = walk(n.child[0]);      // recurse first
  Result b = walk(n.child[1]);
  return combine(n.kind, a, b);       // then use the results
}

Every tree walk in this course is a variation on this. Termination is automatic as long as every recursive call goes to a strictly smaller subtree — which is true for any finite tree. The one place it bites is when a "tree" secretly has a cycle (a grammar rule that refers to itself with no base case); Module 16 is about spotting and removing those.
