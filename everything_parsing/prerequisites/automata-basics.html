Automata Basics

A finite automaton is a machine with a fixed, finite amount of memory — one variable holding "which state am I in." That single constraint is what the whole regular/context-free split turns on.

01

The five parts

A deterministic finite automaton (DFA) is (Q, Σ, δ, q₀, F):

  • Q — a finite set of states
  • Σ — the input alphabet
  • δ : Q × Σ → Q — the transition function: given the current state and the next input symbol, the next state. Total — defined for every pair.
  • q₀ ∈ Q — the start state
  • F ⊆ Q — the accepting (final) states

To run it on a string: start at q₀, apply δ once per symbol, and accept iff you end in a state in F. The language of the automaton is the set of strings it accepts.

  "an even number of a's" over {a, b}

02

NFA — the same, but δ may branch

A nondeterministic finite automaton lets δ map a (state, symbol) pair to a set of states — including the empty set (no move) — and allows ε-transitions (move without consuming input). It accepts a string if some path through the choices ends in an accepting state.

NFAs are not more powerful — Module 13's subset construction turns any NFA into a DFA for the same language — but they are far easier to build, which is why Thompson's construction (Module 12) targets an NFA.

03

The pigeonhole principle — why finite memory is a real limit

Pigeonhole

If you put n + 1 items into n boxes, some box holds at least two.

Applied to a DFA with p states: reading a string of length p visits p + 1 states (before the 1st symbol, after the 1st, … after the pth). Only p states exist, so two of those visits are to the same state. The input consumed between those two visits forms a loop — and the automaton cannot tell how many times that loop was taken. That is the entire engine of the pumping lemma (Module 7).
