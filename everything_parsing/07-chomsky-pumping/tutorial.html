Everything Parsing · Module 07 · Part I — Foundations

The Hierarchy &the Pumping Lemma

Grammars come in strength classes. A regular grammar has a fixed, finite memory and provably cannot match aⁿbⁿ. A context-free grammar can, but provably cannot match aⁿbⁿcⁿ. This module runs the pumping argument as code: for any claimed limit, it hands back the exact string that breaks it.

The whole result in one sentence

Type 3 ⊊ Type 2 ⊊ Type 1 ⊊ Type 0. Each class is strictly weaker than the next, and a*, aⁿbⁿ, aⁿbⁿcⁿ are the witnesses that pry them apart. This is why the course has a separate lexing track and parsing track — different provable amounts of power.

01

The Big Analogy — the doorman with a wrapping clicker

A doorman at a venue holds a hand clicker. His job: let people in, then let exactly the same number back out, and no more. aⁿbⁿ — n in, then n out.

His clicker has p positions and then it wraps back to zero. That's his entire memory. Feed him p arrivals and the clicker has cycled at least once. Now feed him k more, landing on the same position a wrap earlier hit. From his point of view, "p people came in" and "p + k people came in" are indistinguishable — same clicker reading.

So when he lets p people out and stops, he's happy — but if p + k actually came in, he just approved an unbalanced night and never knew. The k extra arrivals are a segment you can repeat as many times as you like and he can't tell.

A regular grammar is that doorman: finitely many states, so on a long enough string it must revisit one, and the loop between the two visits is a segment you can pump — repeat or delete — with the grammar none the wiser. If the target language forbids that (pumping the a-part of aⁿbⁿ unbalances it), no regular grammar can be recognising that language.

02

What Happens, Step by Step

  1. Classify the grammar. Every production A → w or A → w B (nonterminal only at the end) → right-linear (regular). A → B w → left-linear (regular). A nonterminal in the middle, or two of them → context-free.
  2. State the regular pumping lemma. If L is regular, there exists p such that every s ∈ L with |s| ≥ p splits as xyz (|y| ≥ 1, |xy| ≤ p) with xyᵏz ∈ L for all k.
  3. Refute it for {aⁿbⁿ}. For any claimed p: take s = aᵖbᵖ. |xy| ≤ p forces y to be all as. Then xy²z has more as than bs → ∉ L. Every split fails. No p works. Not regular.
  4. Do it in code: for p = 1…8, enumerate all p(p+1)/2 splits and confirm each escapes under pumping.
  5. One level up: the context-free pumping lemma splits s into five parts uvwxy with |vwx| ≤ p. Run the same refutation against {aⁿbⁿcⁿ} — |vwx| ≤ p means it can't touch both as and cs, so pumping unbalances the counts.
03

The state, drawn

Why a p-state machine must repeat on aᵖ

  reading  a a a a a ... a      (p of them)
  state    q0 q1 q2 q3 ...      (p+1 states visited, only p exist)
                 └──────┘
                 pigeonhole: two of q0..qp are the same state, say q_i = q_j (i < j)

  x = a^i        the part before the repeat
  y = a^(j-i)    the LOOP between the two visits to the same state   ← pump this
  z = a^(p-j) b^p   the rest

  x y^2 z = a^(i + 2(j-i) + (p-j)) b^p = a^(p + (j-i)) b^p     more a's than b's  →  NOT in { a^n b^n }

The tower

  ┌─────────────────────────────────────────────── Type 0  recursively enumerable
  │  {  : M halts on w }                       Turing machine
  │  ┌──────────────────────────────────────────── Type 1  context-sensitive
  │  │  a^n b^n c^n                                 linear-bounded automaton
  │  │  ┌───────────────────────────────────────── Type 2  context-free
  │  │  │  a^n b^n , balanced parentheses           pushdown automaton (stack)
  │  │  │  ┌────────────────────────────────────── Type 3  regular
  │  │  │  │  a* , (a|b)*abb , identifiers          finite automaton (no memory)
  │  │  │  └──────────────────────────────────────
  │  │  └─────────────────────────────────────────
  │  └────────────────────────────────────────────
  └───────────────────────────────────────────────
      each box STRICTLY inside the next — proven by the pumping lemmas

The Code, Explained

Classifying by right-hand-side shape

for (Grammar.Production p : g.productions) {
  // count nonterminals in the rhs, note the first and last positions
  int nts = ..., firstNt = ..., lastNt = ...;
  if (nts == 0) continue;                          // A -> w : fine either way
  if (nts > 1) { allRight = allLeft = false; continue; }
  if (lastNt != rhs.size() - 1) allRight = false;    // nonterminal not at the end
  if (firstNt != 0)               allLeft  = false;    // nonterminal not at the start
}

S → a S b has one nonterminal, in the middle → neither → context-free. That's not a limitation of our grammar — {aⁿbⁿ} is provably not regular, so no grammar for it is linear.

The adversary — every split escapes

Crazy detail — the lemma is one-directional

Regular ⟹ pumpable. The converse is false: there are non-regular languages that do satisfy the pumping condition, so passing the pumping test proves nothing. The lemma is only a tool for proving a language is not regular. To prove one is regular, you build a DFA or a regex (Part II). See the Brain Exercise.

05

Limits — what this module cannot do yet

Can't do yet

  • Prove a language is regular — the pumping lemma is a one-way tool; you need a DFA/regex (Part II).
  • Decide whether an arbitrary CFG generates a regular language — that's undecidable.
  • Build the pushdown automaton or the linear-bounded automaton that recognise Types 2 and 1.
  • Handle Type 0 / Type 1 grammars — our file format only expresses single-nonterminal-lhs (≤ Type 2).

Can do

  • Classify any file grammar as right-linear, left-linear, or context-free.
  • Run the regular pumping lemma as an adversary and show it has no valid pumping length for {aⁿbⁿ}.
  • Run the context-free pumping lemma the same way for {aⁿbⁿcⁿ}.
  • Enumerate the exact string that breaks any claimed bound.
  • State the hierarchy and its separating witnesses precisely.

Getting a blank or broken result?

A grammar you think is regular classifies CONTEXT_FREE — it has a nonterminal not at the end (right-linear) or start (left-linear), or two nonterminals. S → a S b is not regular.
allEscaped is false — the escape-k set {2, 0, 3} didn't cover a pump-breaking value for your language. For aⁿbⁿ and aⁿbⁿcⁿ, k = 2 always works.
cflRefutation is slow — the 5-part loop is O((3p)⁴). Keep p small; the demo stops at 4.

07

Brain Exercise

(1) The refutation proves {aⁿbⁿ} is not regular. Does it prove {aⁿbⁿ} is context-free? What would?

(2) Is { aⁿ : n is prime } regular? Prove your answer with the pumping lemma.

Answers

(1) No. The pumping lemma is one-directional — it can only ever prove "not regular." {aⁿbⁿ} being context-free is established by exhibiting a CFG for it, which Module 4 did: S → a S b | ε. "Not regular" and "is context-free" are proven by completely different means — a refutation vs. a construction.

(2) Not regular. Suppose it were, with pumping length p. Pick a prime q > p and s = aᵍ. Split s = xyz with |y| = d ≥ 1. Pump to xyⁱz = a^(q + (i-1)d). Choose i - 1 = q: the exponent is q + qd = q(1 + d) — a product of two integers each > 1, so composite. Then xyⁱz ∉ L, contradicting the lemma. Every unary non-eventually-periodic language falls the same way.

08

There Are No Dumb Questions

Why does aⁿbⁿ matter? No real language literally has that.

Every nested structure is aⁿbⁿ-shaped: balanced parentheses, matched { }, begin/end, opening and closing XML/HTML tags, nested function calls, arithmetic with parentheses. A finite-state machine cannot check that nesting balances, which is the reason lexing (regular) and parsing (context-free) are separate phases with separate power.

Regex libraries support (a+)\1 — isn't a backreference counting?

Yes, and that's exactly why a regex with backreferences is not matching a regular language any more. (a+)\1 matches { aⁿaⁿ } = { a²ⁿ } — still regular by luck — but (a+)b\1 matches { aⁿbaⁿ }, which is not regular. "Regex" as a library feature and "regular expression" as a formal object parted ways when backreferences were added.

Is there an algorithm to decide "is this grammar regular"?

Two different questions. "Is this grammar right/left-linear?" — trivially decidable, it's a syntactic check (that's classify). "Does this grammar generate a regular language?" — undecidable for context-free grammars. A context-free grammar can generate a regular language (S → a S | a generates a⁺), and no algorithm always detects that.

The classifier called S -> a S b context-free. Couldn't a cleverer grammar for the same language be regular?

No — and that's the deep point. {aⁿbⁿ} is not a regular language (this module proves it), so every grammar that generates it fails to be right- or left-linear. The property belongs to the language, not to your choice of grammar.

If the pumping lemma can't prove "regular," what's the point of Part II?

Part II builds the positive tools: a DFA is a proof that a language is regular, and Thompson's construction turns any regex into one. This module draws the ceiling; Part II builds up to it and then Part III goes above it.
