Everything Parsing · Module 02 · Part I — Foundations

Alphabets, Strings,Languages

Four words the whole field stands on, made exact — and one claim, proven in code: union, concatenation, and power take finite languages to finite languages. Only Kleene star escapes to infinity, and that single asymmetry is why the next twenty modules exist.

The payoff line

A regular expression is nothing but union, concatenation, and star. This module builds those three as set operations and reconstructs (a|b)a* from them, string for string — before Module 3 has written a single line of regex-parsing code.

01

The Big Analogy — the bead kit

On the table: a jar of coloured beads. The set of colours in the jar is the alphabet, Σ. Thread some beads on a cord and you have a bracelet — an ordered sequence. The bare cord with nothing on it is still a bracelet: the empty string, ε.

Now you have drawers. Each drawer of bracelets is a language — you decided those bracelets belong together. Operations act on whole drawers:

  • Union — tip drawer A and drawer B into one drawer.
  • Concatenation — for every bracelet in A and every bracelet in B, clasp them end to end; the results fill a new drawer. (|A|·|B| bracelets.)
  • Kleene star — start from the bare cord, keep clasping on more copies of drawer A's bracelets. Forever — or, in practice, until they're longer than your wrist.

And the trap this analogy has to make obvious: an empty drawer (∅) is not a drawer holding one bare cord ({ε}). Clasp every bracelet in A onto "a bracelet drawn from the empty drawer" and you produce nothing — there was nothing to draw (∅ · A = ∅). Clasp them onto the bare cord and each comes back unchanged ({ε} · A = A).

02

What Happens, Step by Step

  1. Alphabet. Fix a finite set of symbols, e.g. Σ = {a, b}.
  2. String. A finite sequence of symbols from Σ. Length can be 0 (that's ε = "").
  3. Σ*. The set of all strings over Σ — infinite. We compute it up to a length as the bounded star of the one-character languages: {a}, {b} starred.
  4. Language. Any set of strings. We store finite ones, in a canonical order: shorter strings first, ties broken lexicographically.
  5. Union = set union. Concatenation = { xy : x∈L₁, y∈L₂ }, a double loop. Power Lⁿ = concat with self n times; L⁰ = {ε}.
  6. Kleene star = breadth-first closure: from {ε}, repeatedly prepend strings of L, keep everything ≤ the bound, dedupe.
  7. Closure check. Every result above from finite operands is finite — except star, whose true result is infinite, which is why it alone needs a bound.

{ε} and ∅ under concat — the whole difference

  ∅ · {a, b}   :  for x in ∅ ... (loop body never runs)      →  { }        ∅ annihilates
  {ε} · {a, b} :  x = "" ;  "" + "a" = "a" ,  "" + "b" = "b"  →  { a, b }   {ε} is identity
04

The Code, Explained

Concatenation — the definition, verbatim

If strings is empty the outer loop never runs → ∅ · L = ∅. If strings = {""} then x = "" and "" + y = y → {ε} · L = L. The identities are not coded; they are what the double loop does.

Kleene star — why the seen-set is load-bearing

Language star(int maxLen) {
  Set<String> acc = new HashSet<>();  acc.add("");
  Deque<String> work = new ArrayDeque<>();  work.add("");
  while (!work.isEmpty()) {
    String prefix = work.poll();
    for (String s : strings) {
      String next = prefix + s;
      if (next.length() > maxLen) continue;
      if (acc.add(next)) work.add(next);   // only enqueue genuinely new strings
    }
  }
  return new Language(acc);
}
Why not just power(0) ∪ power(1) ∪ power(2) ∪ …?

Because that loop needs a stopping rule, and the obvious one — "stop when power(k) adds no new string ≤ maxLen" — never fires when ε ∈ L. If L = {"", "a"}, every power(k) still contains ε and a, so it always looks like there's more to do. The closure form with a seen-set terminates for every L — with ε, without it, and for L = ∅ (result {ε}). See DECISIONS.md #5.

The regular expression, rebuilt from the three methods

// (a|b) a*   ,  clipped to length <= 4 for display
Language firstChar = Language.of("a").union(Language.of("b"));
Language tail      = Language.of("a").star(3);
Language re        = firstChar.concat(tail);
// → { a, b, aa, ba, aaa, baa, aaaa, baaa }
//   "b"  in L    "ba" in L    "ab" NOT in L    ""  NOT in L

Three method calls. That is the entire semantic content of the regex (a|b)a*. Module 3 adds a parser that turns the six characters (a|b)a* into a tree of Union / Concat / Star nodes — but each node will just call one of these methods.

05

Limits — what this module cannot do yet

Can't do yet

  • Represent an infinite language. Only bounded slices — star and sigmaStar both take a length.
  • Decide membership in an infinite language without generating a bounded chunk of it.
  • Parse regex notation — there is no (a|b)* string parser yet (Module 3).
  • Match efficiently. Enumerating Σ*≤n is |Σ|ⁿ⁺¹-ish strings; a real matcher simulates an automaton (Modules 10–13).
  • Say anything about context-free languages — concat/star can't build aⁿbⁿ as one operation.

Can do

  • Compute union, concatenation, and every finite power exactly.
  • Show, by fully listing every result, that finite in → finite out for all three.
  • Compute Kleene star up to any length bound, terminating for every input including ε ∈ L.
  • Reproduce any regular expression's meaning as a bounded set, purely from the three operations.
  • Demonstrate {ε} ≠ ∅ concretely: identity vs. annihilator under concat.

Getting a blank or broken result?

star never returns — you passed a large maxLen. |Σ*≤n| grows as |Σ|ⁿ; length 6 over a 4-symbol alphabet is already 5461 strings. Keep bounds small.
Render order looks wrong — strings sort by length first, then lexicographically. "bb" comes after "aa" and "ab", but all three come before any 3-character string.
{ epsilon } and {} behave the same in your port — you stored the empty string as null or skipped it. "" is a value; put it in the set.

07

Brain Exercise

(1) power(n) always terminates with no seen-set; star needs one. In one sentence, what is the structural difference between the two loops that makes this true?

(2) Is concatenation commutative? Find L₁, L₂ with L₁ · L₂ ≠ L₂ · L₁. Is it associative?

Answers

(1) power(n) does a fixed number of concatenations — exactly n, known before the loop starts — so it can't run forever. star loops until a data-dependent condition ("no new strings ≤ bound"), and without a seen-set a language containing ε re-generates strings it has already seen and the condition never becomes true.

(2) Not commutative: {a} · {b} = {ab} but {b} · {a} = {ba}. It is associative — (L₁·L₂)·L₃ = L₁·(L₂·L₃) — because string concatenation is associative, so the grouping of the clasps doesn't matter. Union is both commutative and associative (it's set union). This is why (a|b)a* is unambiguous about the · but a|b|c needs no parentheses either — Module 6 makes the difference precise.

08

There Are No Dumb Questions

Isn't a string just a list of characters? Why the ceremony?

Operationally, yes. Conceptually, a string is an element of Σ* — the free monoid over Σ: concatenation is its operation, ε its identity, and it's associative but not commutative. That structure is exactly what makes power and star well-defined, and it's the same structure a parser exploits when it reads left to right.

Why is {ε}·L = L but ∅·L = ∅? They look similar.

concat pairs every x in the first set with every y in the second. ∅ has no x, so there are zero pairs → empty result. {ε} has exactly one x = "", and "" + y == y → you get every y back. One set is empty; the other contains one (very short) element. That's the entire difference and it changes the outcome completely.

You said regex = union + concat + star. What about +, ?, [a-z], .?

All sugar over the three. a+ = a·a*. a? = a|ε. [a-z] = a|b|…|z. . = the union of every symbol in Σ. Backreferences (\1) are the exception — they take you outside regular languages entirely, which is why "regex" engines that support them aren't really matching regular languages any more.

Why bound Kleene star? Real regex engines match infinite languages fine.

They don't enumerate the language — they simulate a finite automaton that accepts or rejects one input string in linear time (Modules 10–13). Enumerating L* is only for seeing the definition. No production matcher ever lists the language.

Could I use this Language type to check if two regexes are equivalent?

Only approximately — compare their bounded enumerations up to some length and hope no difference hides past the bound. The exact answer needs minimal-DFA comparison (Module 14): build the minimal automaton for each, check they're isomorphic. For regular languages that's decidable; for context-free ones it's undecidable, a fact that shapes Part IV.
