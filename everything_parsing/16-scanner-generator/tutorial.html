The ScannerGenerator

Write down a language's tokens as a short spec file, and get a working lexer back. Every pattern becomes an NFA, the NFAs are joined and determinized into one DFA, and a single left-to-right pass turns source text into tokens stamped with line and column. The spec here is the complete lexical grammar of Ajoda, a small typed language, so the output is a lexer you could hand straight to a parser.

28 lines of spec, one DFA, a real language

28 rules → 1 DFA of 287 states over 97 input symbols. iffy while1 truest → IDENT IDENT IDENT. a<=b → IDENT LE IDENT. A spec rule like [+\-]? is refused before scanning starts, because it can match nothing at all.

01

The Big Analogy — a sorting office with one conveyor belt

A post office receives one long strip of paper with many letters glued end to end. It needs them cut apart and dropped into labelled bins.

The slow way is a row of clerks, one per bin, each checking whether the strip starts with "their" kind of letter. The fast way is one cutting machine that has every bin's rules built into it. The strip feeds in one character at a time. At every moment the machine knows which bins the paper so far could still belong to, and whether it would be a complete letter if it were cut right here.

The machine keeps feeding as long as some bin is still possible. When nothing more fits, it backs up to the last place a cut was valid, cuts, and drops the piece in that bin. If two bins claim the same piece, the bin listed first in the rulebook wins. Packing tissue between letters (whitespace and comments) goes straight into the recycling bin.

Two extra rules. Letters addressed with a reserved name (if, while) are pulled out of the general "name" bin after the cut, so iffy stays one letter. And the machine refuses a rulebook in which some bin accepts a zero-length letter: it would cut nothing, forever, without moving the belt.

What Happens, Step by Step

THE SPEC (fixtures/ajoda.tokens, excerpt):

token    IDENT      [A-Za-z_][A-Za-z0-9_]*
token    FLOAT_LIT  [0-9]+"."[0-9]+
token    INT_LIT    [0-9]+
token    ARROW      "->"
token    LPAREN     \(
discard  SPACE      [\s\t\n]+
discard  COMMENT    "//"[^\n]*
keywords IDENT      fn let if else while return true false i64 bool f64

BUILD:

  1. Read directives. token emits, discard matches and drops, keywords names the rule whose lexemes get looked up afterwards. Unknown directives and duplicate names are spec errors with a line number.
  2. Desugar each pattern (pattern.mjs / Pattern.java). Classes, ranges, negation, escapes and quoted literals all compile down to Module 3's six node kinds, so [0-9] is just 0|1|…|9.
  3. Refuse empty matches. Thompson-build the pattern; if εClosure({start}) ∩ accept ≠ ∅, the pattern accepts "" and the spec is refused.
  4. Join and determinize. A fresh START gets an ε-edge into each rule's NFA, every accept state is tagged with its rule index, and the subset construction (Module 13) builds the DFA. Each DFA state is labelled with the smallest rule index among its tagged NFA states.

SCAN (from pos = 0, line = 1, col = 1):

  1. Step the DFA over src[pos..]. Whenever it enters a labelled state, record (end = i+1, rule). Stop at a character outside the alphabet or at the dead state.
  2. No record → ScanError at line:col.
  3. Otherwise the lexeme is src[pos..end]. For a token rule, emit it (after a keyword lookup). For a discard rule, emit nothing.
  4. Walk the lexeme to update line and col, set pos = end, repeat. Finish with an EOF token.

The Code, Explained

Labelling each DFA state with its winning rule

// legend: DFA state name -> the set of NFA states it stands for
for (var e : Subset.legend(combined).entrySet()) {
  if (e.getValue().isEmpty()) sink = e.getKey();     // the dead state
  int best = Integer.MAX_VALUE;
  for (String s : e.getValue()) {
    Integer ri = acceptRule.get(s);                   // null unless s is a tagged accept
    if (ri != null && ri < best) best = ri;
  }
  if (best != Integer.MAX_VALUE) stateRule.put(e.getKey(), best);
}

Longest match

Crazy detail — four characters need a stage name

The automaton text format from Module 10 splits fields on whitespace and treats # as a comment. So a space, a tab, a newline or a # can't appear there as themselves. The pattern layer renames them SP, TAB, NL and HASH on the way in, and the scanner applies the same symbolOf to each source character on the way through. Every other printable ASCII character is its own symbol. None of the automaton code had to change.

Crazy detail — the dead state costs you O(n²) if you ignore it

The subset construction builds a state for the empty set of NFA states and loops it back to itself. If the scan loop only stopped at the end of input, every token would walk the rest of the file first. Stopping at sink keeps scanning linear.

05

Limits — what this module cannot do yet

Can't do yet

  • Minimize the DFA. Plain minimization would merge states that accept different rules (see Brain Exercise).
  • Keep going after a bad character (Module 17).
  • Block comments, nesting, string escapes (Module 18).
  • Anything beyond ASCII. The alphabet is tab, newline and 0x20–0x7E.

Can do

  • Build a working lexer for a real language from a text spec.
  • Classes, ranges, negation, escapes and quoted literals, all desugared to six node kinds.
  • Longest match with first-declared tie-breaking, in one pass.
  • Keywords by table lookup, so prefixes never split identifiers.
  • line:col on every token, including after comments.
  • Refuse an empty-matching pattern before scanning starts.

Getting a blank or broken result?

X accepts the empty string: the whole pattern is optional (a?, [0-9]*, ()). Make at least one piece required.
bare whitespace at column N: write \s, \t or a quoted " " inside a pattern.
A keyword comes out as IDENT: it's missing from the keywords line, or the line names the wrong source rule.
Columns drift after a comment: line and col must advance over discarded lexemes too.

07

Brain Exercise

(1) Minimize the 287-state DFA using the usual starting split "accepting vs non-accepting". What goes wrong, and what starting split fixes it? (2) Move INT_LIT above FLOAT_LIT in the spec. Does any output change? Why or why not?

Answers

(1) Two accepting states that behave the same on all future input get merged even if one accepts IDENT and the other accepts INT_LIT, and the merged state can't say which token it found. Start instead with one block per rule label plus one block for unlabelled states. Refinement then never mixes two different rules.

(2) Nothing changes. Declaration order only matters when two rules accept the same lexeme, and no string is both an INT_LIT and a FLOAT_LIT. Longest match already decides 3 vs 3.14. Order does matter for, say, two rules that both accept =.

08

There Are No Dumb Questions

Why not give keywords their own rules above IDENT?

That works too; longest match plus first-declared tie-breaking gets it right. But every keyword then adds NFA states, and the DFA grows. A lookup table after the cut costs one hash probe per identifier and keeps the DFA the same size no matter how many keywords the language has. Ajoda's own lexer design calls for exactly this.

Why refuse empty-matching patterns instead of just skipping them?

A pattern that can match nothing will "match" at every position without moving. The scan loop requires end > pos, so it wouldn't hang, but the rule would silently never fire for the input its author intended. Refusing at load makes the mistake visible on the line that caused it.

287 states for a small language: is that a lot?

For an un-minimized DFA over 97 symbols, it's normal. Thompson's construction leaves lots of ε-scaffolding, and character classes become wide unions. Label-aware minimization and table compression (what flex and re2c do) shrink it dramatically. This module leaves it un-minimized so the construction stays visible.

Where does the Ajoda spec come from?

From Ajoda's lexical grammar: identifiers, integer and float literals, the operator set, // comments and the reserved-word table. The spec file is a line-for-line transcription of it, which is the point: a scanner generator should let you write the grammar down once and get the lexer for free.
