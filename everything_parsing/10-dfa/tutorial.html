DeterministicFinite Automata

A DFA is a five-tuple (Q, Σ, δ, q₀, F) where δ is a total function Q × Σ → Q. It decides membership in one left-to-right pass with only its current state as memory — and the set it accepts is exactly a regular language, not one string more.

The proof and the limit, side by side

The 4-state DFA for (a|b)*abb accepts the same 15 strings (up to length 6) as the Module-3 regex — checked both ways. And a DFA for a*b* is caught red-handed accepting aaab: with finitely many states, it cannot count.

01

The Big Analogy — the bellhop who remembers nothing

You hand a bellhop a slip of paper with a string of letters on it. He starts in the lobby. For each letter, he reads the hallway sign for that letter and walks to exactly the one room it points to — no choice, no backtracking. When the letters run out, if he's standing in a room with a green door, your reservation is confirmed.

Here's the constraint that makes a DFA a DFA: the bellhop remembers nothing except which room he's currently in. Not the letters he's read, not how many, not the path he took. Every room's hallway signs depend only on the letter — so his entire knowledge of the past is compressed into "which of the hotel's finitely many rooms am I in."

Give him aⁿbⁿ to check. He walks down the a corridor. The hotel has, say, 20 rooms, so after 20 as he's revisited one — and from then on he's in a loop. He genuinely cannot tell a walk of 20 as from a walk of 25. So when the bs come, he can't check the count matches. No hotel with finitely many rooms can.

02

What Happens, Step by Step

  1. Load states, alphabet, start, accepting set, and one transition per line (from symbol to).
  2. Complete δ. Any (state, symbol) with no line → transition to <dead>. <dead> self-loops on everything. Now δ is total.
  3. Run on an input: state = q₀; for each symbol, state = δ(state, symbol). Accept iff state ∈ F at the end.
  4. Enumerate the language: generate every string over Σ up to a length bound; keep the ones that run to an accepting state.
  5. Cross-check: the enumerated language must equal the Module-3 regex's, both directions, up to the bound.
  6. Show the limit: run on one symbol repeated; by pigeonhole two prefixes hit the same state — the machine's blind spot.

The state, drawn

The DFA for (a|b)*abb — states track "how much of abb we've matched"

            b            a            b            b
          ┌───┐        ┌───┐        ┌───┐        ┌──────────┐
          ▼   │        ▼   │        │   │        │          │
   ──▶ ( S )──┴──a──▶( A )┴──b──▶( AB )──b──▶(( ABB ))     │
        ▲                ▲          │            │  │       │
        │                └────a─────┘            │  └───a───┘  (back to A)
        └──────────────────b─────────────────────┘  (ABB on b → S)

   run "aabb":   S --a--> A --a--> A --b--> AB --b--> ABB      ACCEPT
   run "abba":   S --a--> A --b--> AB --b--> ABB --a--> A      reject

The pigeonhole loop that stops a*b* from being aⁿbⁿ

  a*b* DFA:   ──▶(( A ))──b──▶(( B ))──a──▶( <dead> )
                   │  ▲          │  ▲            │  ▲
                   └a─┘          └b─┘            └ab┘

  run "a a a a ...":   A --a--> A --a--> A --a--> A ...   never leaves A

  repeatOn('a') = (0, 1):  same state (A) after 0 a's and after 1 a
  → the machine has NO way to know how many a's it saw
  → it accepts "aaab", "abbb", "aabb" — none of which are in { a^n b^n }
04

The Code, Explained

The whole simulator

That's it. No stack, no recursion, no lookahead. The machine's power is entirely in the structure of delta — and its weakness is that state is the only thing carried from one character to the next.

Completing δ to total — the dead state

// after loading: any (state, symbol) with no transition gets routed to DEAD
boolean needDead = false;
for (String s : states)
  for (String sym : alphabet)
    if (!delta.getOrDefault(s, Map.of()).containsKey(sym)) needDead = true;
if (needDead) {
  states.add(DEAD);
  for (String s : states)
    for (String sym : alphabet)
      delta.computeIfAbsent(s, k -> new LinkedHashMap<>()).putIfAbsent(sym, DEAD);
}
Why total matters

A transition table with holes isn't a DFA — it's an NFA (Module 11), where "no move" is a legal outcome. Forcing every (state, symbol) to a real state is precisely what makes step() a function and accepts() a simple loop with no "what if there's nowhere to go?" branch.

05

Limits — what this module cannot do yet

Can't do yet

  • Build a DFA from a regex — you write the transition table by hand (Modules 12–13 automate it).
  • Minimise a DFA — ends-abb happens to be minimal; proving it is Module 14.
  • Accept any non-regular language — no aⁿbⁿ, no nesting, no counting.
  • ε-moves or branching — δ is a single-valued function (that's Module 11).
  • Emit tokens — a DFA says yes/no; a lexer needs "which token, and how long" (Modules 15–16).

Can do

  • Decide membership in any regular language in one O(n) pass, constant memory.
  • Trace the exact state sequence for any input.
  • Enumerate the accepted language up to a length bound.
  • Cross-check that language against the Module-3 regex engine, both directions.
  • Exhibit the pigeonhole repeat that proves "a DFA cannot count".
  • Route undefined transitions to a trap state so δ is genuinely total.

07

Brain Exercise

(1) The ends-abb DFA has 4 states. Is that the fewest possible? How could you tell without trying every smaller machine?

(2) even-a has 2 states. Could a 1-state DFA accept "an even number of as"?

Answers

(1) Yes, 4 is minimal — and you tell by the Myhill–Nerode argument (Module 14): count the distinguishable "futures." After reading some prefix, the only thing that matters is how much of the suffix abb you've matched: nothing / just a / ab / abb. Four cases → at least four states, and the DFA has exactly four, so it's minimal. The number of states of a minimal DFA equals the number of these equivalence classes.

(2) No. A 1-state DFA has one state that is either accepting or not, and every transition loops back to it — so it accepts either every string or none. "Even number of as" is neither Σ* nor ∅ (it accepts "" and aa, rejects a), so it needs ≥ 2 states — and 2 suffice.

08

There Are No Dumb Questions

Why "deterministic"? What's the non-deterministic version?

An NFA (Module 11) lets δ(q, a) be a set of states — zero, one, or many — and allows ε-moves that don't consume input. It accepts if some path through the choices ends accepting. Same expressive power (Module 13 converts one to the other), but an NFA is far easier to build from a regex, which is why Thompson's construction targets it.

The dead state loops forever doing nothing. Isn't that wasteful?

It's what makes δ total, which is what makes it a DFA. A minimal DFA drops the dead state if no accepting state is reachable from it (which is always) and the definition is relaxed to allow a partial δ. Real lexer implementations usually make it implicit — a null from the table means "reject and stop." The formal object keeps it explicit.

Can a DFA have infinitely many states?

Then it isn't a finite automaton. Add an unbounded stack and you get a pushdown automaton (context-free); add an unbounded tape and you get a Turing machine. The DFA's entire power — and its limit — comes from being forced to squeeze all of history into finitely many states.

How do I get a DFA from a regex without hand-writing the table?

Module 12 compiles the Module-3 regex tree into an NFA (Thompson's construction, one gadget per node). Module 13 flattens that NFA into a DFA (subset construction). Module 14 minimises it. This module is the target of that pipeline — worth understanding on its own first.

Is accepts really O(n)? What about the alphabet check every character?

alphabet.contains(sym) is a hash-set lookup — O(1). So each character costs one hash lookup plus one map lookup, and the whole scan is O(n) with a small constant. That linear, constant-memory guarantee is the reason lexers are built on DFAs.

What's Next

Hand-writing a DFA table is tedious and error-prone. Module 11 — NFA and ε-NFA loosens the rules: δ may branch to several states or to none, and ε-transitions move without consuming input. You'll build an NFA simulator that tracks a set of current states, implement ε-closure, and prove — by construction — that this freedom buys zero extra power. That freedom is exactly what Module 12 needs to compile the Module-3 regex tree into an automaton, one small gadget per node.
