Everything Parsing · Module 13 · Part II — Lexical Analysis

SubsetConstruction

Turn any NFA into an equivalent DFA by making each DFA state a set of NFA states — "everywhere a clone could be." Only the reachable sets get built, so the DFA is usually small — but in the worst case it is exactly 2ⁿ, and this module exhibits that case.

The pipeline is complete

regex → (Thompson) → ε-NFA → subset construction → DFA. The Thompson NFA for (a|b)*abb — 14 states — determinizes to a 5-state DFA with the identical language, cross-checked against the regex engine and Module 10's hand-built DFA.

01

The Big Analogy — hire the one meticulous detective

Module 11's NFA detective cloned themselves at every fork. Effective, but you're paying a lot of detectives.

Instead, hire one meticulous detective who never clones. At every step they keep a checklist of every room a clone could be in. New evidence comes in ("the letter a"): they cross off every room, and for each one that was checked, tick the rooms it leads to on a — then tick every room reachable from those through an unlocked door (ε). The new checklist is the new situation.

The case is solved the moment the culprit's room appears anywhere on the current checklist. One detective, one checklist per step, entirely deterministic — that checklist is a DFA state.

The catch: there could be a distinct checklist for every combination of rooms — up to 2ⁿ of them for n rooms. Usually only a handful ever come up. But design the building wrong and all 2ⁿ do.

02

What Happens, Step by Step

  1. Start subset = εClosure({ nfa.start }). Name it D0, put it on a worklist.
  2. Take a subset S off the worklist. For each input symbol a:
    • moved = ⋃ nfa.move(s, a) for every s ∈ S
    • T = εClosure(moved)
    • if T is a subset we haven't seen (keyed by its sorted contents), name it D(next) and enqueue it
    • record the DFA transition S -a-> T
  3. Mark S accepting iff S ∩ nfa.accept ≠ ∅.
  4. Repeat until the worklist is empty. Finitely many subsets ⇒ it terminates.
  5. Emit the DFA (states = the Dn, δ from the recorded transitions) and hand it to Module 10's Dfa.parse.

04

The Code, Explained

The worklist loop

Two details that must be exactly right

1. The ε-closure wraps the whole move. T = εClosure(⋃ move(s, a)) — closure on the outside. If you close before moving and not after, you miss states the target can reach for free.
2. Subsets are keyed by sorted contents. {q3,q1} and {q1,q3} are the same DFA state; the key is "q1q3" either way. Key by insertion order and you split one state into many. See DECISIONS.md.

05

Limits — what this module cannot do yet

Can't do yet

  • Produce the minimal DFA — the subset DFA can have redundant states (Module 14).
  • Avoid the 2ⁿ blow-up — for some NFAs the full DFA genuinely is that big.
  • Determinize lazily — this builds the whole reachable DFA up front.
  • Handle an NFA that isn't over a finite alphabet.
  • Emit tokens — still just a yes/no recogniser (Modules 15–16).

Can do

  • Turn any NFA (with or without ε) into an equivalent DFA.
  • Build only the reachable subsets — often far fewer than 2ⁿ.
  • Show each DFA state as the exact set of NFA states it represents.
  • Verify the DFA's language equals the NFA's, the regex's, and Module 10's DFA's.
  • Exhibit an NFA whose DFA is provably 2ⁿ.
  • Complete the regex → DFA pipeline.

k-th-from-end DFA smaller than 2ᵏ — your NFA is missing s0 -a-> s0 or s0 -b-> s0.

07

Brain Exercise

(1) The 14-state Thompson NFA has 2¹⁴ possible subsets but only 5 are reachable. What keeps that number small, and what makes it explode?

(2) "Lazy determinization" builds a DFA state only when some input actually visits it. For one fixed input string of length n, how many DFA states does matching it visit — worst case? So why does lazy determinization help even when the full DFA is 2ᵏ?

Answers

(1) The reachable-subset count equals the number of distinct "right languages" — the Myhill–Nerode classes (Module 14). It stays small when the NFA's runs funnel into a few stable configurations (few states with real choices, ε-structure that converges). It explodes when the machine must track independent facts: the k-th-from-end NFA has to remember k yes/no bits (was position i from the end an a?), and there are 2ᵏ combinations, each a distinct class.

(2) Matching one string of length n visits at most n + 1 DFA states — one per prefix. So even if the full DFA has 2ᵏ states, any single match touches a linear number. Lazy determinization (RE2, GNU grep) builds and caches only those, getting DFA-speed matching without ever materialising the exponential table — and it caps the cache, falling back to NFA simulation if it grows too big.

08

There Are No Dumb Questions

Is the DFA the subset construction produces minimal?

No. It has no unreachable states, but it can still have two states with the same future behaviour — redundant. The Thompson NFA for (a|b)*abb determinizes to 5 states; the minimal DFA has 4. Merging the redundant ones is Module 14, and the minimal DFA is unique.

What happens to the empty set ∅ as a subset?

It becomes a DFA state — the dead state. Every symbol maps ∅ → εClosure(∅) → ∅, so it self-loops, and ∅ ∩ F = ∅ so it's non-accepting. A trap you can never leave, exactly as Module 10's <dead>.

Why sort the subset before using it as a key?

A set has no order, but a hash key needs a canonical form. {q1, q3} and {q3, q1} must map to the same DFA state. Sort the members, join them — now both produce the identical key. Skip the sort and you'd create D5 and D8 for the same set, doubling parts of the DFA.

Does determinization always terminate?

Yes. There are only 2ⁿ subsets of an n-state NFA, the worklist adds each subset at most once, and each iteration removes one. Worst case it's exponential time and space, but it always finishes.

Is this how grep and RE2 actually work?

Close. They build an NFA (Thompson-style) and determinise it lazily — a DFA state is constructed the first time an input reaches it, then cached. This gives linear-time matching with a bounded DFA cache; if the cache fills, they fall back to direct NFA simulation. Backtracking engines (PCRE, Perl, Python re, JS RegExp) skip the automaton entirely and can blow up exponentially in time.

09

What's Next

You have regex → NFA → DFA, but the DFA isn't the smallest one. Module 14 — DFA Minimization merges states that behave identically from then on. Two algorithms: partition refinement (Hopcroft's, near-linear) and table-filling (all pairs, easy to trace). Myhill–Nerode guarantees the result is unique — there is exactly one minimal DFA per regular language — which also gives you a decision procedure for "do these two regexes denote the same language?" Then Module 15 puts the minimal DFA to work for maximal-munch tokenisation.
