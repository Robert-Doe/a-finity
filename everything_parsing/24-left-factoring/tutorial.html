Left Factoring

Left recursion is gone (Module 23). One obstacle to LL(1) remains: two alternatives of a rule that begin with the same tokens. stmt → id ( args ) | id = expr — the parser sees id and cannot yet tell which rule it's in. The fix is algebra: factor out the common prefix. A → αβ₁ | αβ₂ becomes A → α A', A' → β₁ | β₂ — read the α once, decide after.

The payoff

S → if b then S | if b then S else S | other factors to S → other | if b then S S', S' → ε | else S — the exact grammar Modules 20 and 22 dissected. It came from here.

The Big Analogy — the choose-your-own-adventure with a duplicated page

Two entries in the book: "Walk to the old bridge and cross it. On the far side, turn left → page 40" and "Walk to the old bridge and cross it. On the far side, turn right → page 55." A reader deciding at the fork has to read almost the whole sentence before the two options diverge. Worse, if they commit early and guess wrong, they have to come back and re-read.

A good editor merges the shared text: "Walk to the old bridge and cross it. On the far side: to turn left → page 40; to turn right → page 55." Now the shared part is stated once, and the choice is a single clean branch at the exact point the paths split.

That's left factoring. The shared opening — α — gets pulled into the main rule. A new helper "page" — A' — holds just the parts that differ, β₁ and β₂. The parser walks α with no decision to make, then branches once on A', where the alternatives finally start with different tokens.

02

What Happens, Step by Step

  1. Pick a nonterminal A. Among its alternatives, find the longest symbol sequence α (length ≥ 1) that prefixes at least two of them. (Compare every pair; keep the longest common prefix found.)
  2. If there's no such α, A is done.
  3. Split the alternatives: withα = those starting with α; rest = the others.
  4. Make a fresh nonterminal A'.
  5. New A alternatives: rest, plus one new one α A'.
  6. New A' alternatives: for each member of withα, its suffix after α — a zero-length suffix becomes A' → ε.
  7. Repeat over all nonterminals (including the freshly made A', and A again — it may still have another shared prefix) until a full pass factors nothing.
03

The state, drawn

The dangling else — one long prefix

  S -> if b then S | if b then S else S | other

  pairs:  (0,1) common prefix = [if b then S]   length 4   <- longest
          (0,2) = []      (1,2) = []

  alpha = [if b then S]
  withalpha = { "if b then S" , "if b then S else S" }
  rest      = { "other" }

  S  -> other | if b then S S'
  S' -> epsilon | else S        (suffix of alt 0 is empty; suffix of alt 1 is "else S")

  FIRST(S' -> epsilon)  contributes nothing;  FIRST(S' -> else S) = { else }
  disjoint!  ...but else is ALSO in FOLLOW(S'), so the dangling-else conflict
  (Module 20) is still there. factoring fixed the prefix, not the ambiguity.

Nested prefixes — two passes

  A -> a b c | a b d | a e

  pass 1:  longest shared prefix = [a b]  (alts 0,1)
           A  -> a e | a b A'
           A' -> c | d

  pass 2:  A now has  "a e"  and  "a b A'"  -> shared prefix [a]
           A   -> a A''
           A'' -> e | b A'

  final:   A -> a A''      A'' -> e | b A'      A' -> c | d
           no nonterminal has two alternatives with the same first symbol.

Realistic — three id-prefixed statements

  stmt -> id lp args rp semi | id assign expr semi | id colon type semi

  shared prefix = [id]   (only the first symbol — the rules diverge immediately after)

  stmt  -> id stmt'
  stmt' -> lp args rp semi | assign expr semi | colon type semi
           ^^  ^^^^^^  ^^^^^  three different first tokens -> LL(1) here

Why restart the whole pass after one factoring

factor loops the nonterminals and breaks the moment factorOne changes anything, then starts over. It's the simplest way to be obviously correct: every factoring step strictly reduces the number of alternative-pairs sharing a prefix, so the loop must terminate, and restarting means we never reason about a half-modified grammar. At this scale the cost is nothing.

05

Limits — what this module cannot do yet

Can't do yet

  • Make a grammar LL(1) when the problem isn't a shared prefix — the dangling-else FOLLOW conflict survives factoring.
  • Factor a common prefix that only appears after expanding a nonterminal (e.g. A → B x | C x where B, C can both start with d) — needs FIRST-set reasoning, Module 25's table build surfaces it.
  • Preserve parse-tree shape (the stem nonterminal adds a node).
  • Choose the minimal set of new nonterminals.
  • Prove language preservation in general — checked empirically here.

Can do

  • Factor the longest shared prefix out of any rule.
  • Handle nested prefixes (multiple passes) and empty suffixes (A' → ε).
  • Leave an already-factored grammar untouched.
  • Preserve the language (bounded enumeration).
  • Produce the Module 20/22 dangling-else grammar from the unfactored one.

07

Brain Exercise

(1) Factor E → num | num . num | num e num (integer, float, scientific). What's E'? Is the result LL(1)? (2) Grammar A → B c | B d, B → b. There's no literal shared prefix in A's alternatives (B c vs B d) — or is there? Can you left-factor it?

Answers

(1) Shared prefix num. E → num E', E' → ε | . num | e num. FIRST sets: ε contributes nothing, {.}, {e} — pairwise disjoint, and ./e aren't in a colliding FOLLOW. LL(1). Yes.

(2) The alternatives literally share the first symbol B — it's a nonterminal, but it's still the same symbol, so factor it: A → B A', A' → c | d. (If instead the shared prefix were "two different nonterminals that both start with b," you couldn't fix it by textual factoring — you'd have to inline or accept it's not LL(1). That's the limit noted in §05.)

08

There Are No Dumb Questions

If factoring doesn't always give LL(1), why bother?

Because when a shared prefix is the problem, factoring is the only fix, and it's mechanical. The dangling else has two problems stacked — a shared prefix (fixable) and a FOLLOW conflict (not). Factoring clears the first so the second is the only thing left to reason about.

Does the order I factor prefixes in matter?

It changes which intermediate nonterminals you get, not the language or whether the final grammar is factored. Longest-first tends to produce fewer, more meaningful stems.

What if two alternatives are identical?

They dedupe — a grammar rule is a set of alternatives, and A → x | x is just A → x. The code dedupes after every rewrite.

Is left factoring reversible?

Yes — inline A' back into A (substitute each A' alternative into the α A' rule) and you recover the original. The transforms in Modules 23–24 are all language-preserving and (up to naming) invertible.

Do hand-written recursive-descent parsers left-factor?

Informally, yes: you write code that reads the shared prefix, then switches on the next token. The grammar transform is the formal version for tools that consume productions — the LL(1) table builder (Module 25), the parser generator (Module X15).
