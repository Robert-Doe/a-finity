Everything Parsing · Module 05 · Part I — Foundations

Parse Trees vs.Derivation Order

A derivation is a sequence — this rule, then that one. A parse tree is a structure — what nests inside what. This module shows the tree is the real object: the leftmost and rightmost derivations are just two ways to walk the same tree, using the same rules in a different order.

The claim, made checkable

Build one parse tree for id + id * id. Read the leftmost derivation off it (8 steps). Read the rightmost derivation off it (8 steps). Different sentential forms. Same eight productions. Same tree. The order was never part of the answer.

01

The Big Analogy — the flat-pack bookshelf

You're assembling a flat-pack bookshelf. The booklet has numbered steps: "attach panel A to shelf 1," "attach shelf 1 to upright B," and so on. You follow them top to bottom and end up with a bookshelf.

Your left-handed friend assembles the same kit working from the last step backwards — building the right-hand sub-assembly first, then the left, then joining them. Different order. Different pile of half-built pieces on the floor at any given moment.

The finished bookshelf is identical. Same panels, same screws, same joints. What the object is — which part connects to which — was fixed by the design, not by the order you turned the screwdriver.

The design is the parse tree. The booklet's step order is a leftmost derivation. Your friend's order is a rightmost derivation. The screws-and-joints list is the multiset of productions — identical for both. And "it's a bookshelf" is the string the tree yields.

02

What Happens, Step by Step

  1. Build the tree once. Start with a single unexpanded node [E]. For each production choice, expand the leftmost unexpanded nonterminal: replace it with child nodes, one per right-hand symbol. Each node records the production that expanded it.
  2. The tree has no order. It records which productions and how they nest — not when each was applied.
  3. Read the leftmost derivation: frontier = [root]. Repeatedly find the leftmost frontier node that's an expanded nonterminal, splice in its children, record the new symbol sequence and the node's production. Stop when the frontier is all leaves.
  4. Read the rightmost derivation: the same walk, but always take the rightmost expanded nonterminal.
  5. Compare. Collect every node's production, sort by index → the multiset is identical for both. The yield is identical. Only the intermediate sentential forms differ.

Two walks of that tree, side by side

step   LEFTMOST (expand leftmost NT)     RIGHTMOST (expand rightmost NT)
  0    E                                E
  1    E + T          (E -> E + T)      E + T              (E -> E + T)
  2    T + T          (E -> T)          E + T * F          (T -> T * F)
  3    F + T          (T -> F)          E + T * id         (F -> id)
  4    id + T         (F -> id)         E + F * id         (T -> F)
  5    id + T * F     (T -> T * F)      E + id * id        (F -> id)
  6    id + F * F     (T -> F)          T + id * id        (E -> T)
  7    id + id * F    (F -> id)         F + id * id        (T -> F)
  8    id + id * id   (F -> id)         id + id * id       (F -> id)

  productions, sorted:  [E->E+T, E->T, T->T*F, T->F, T->F, F->id, F->id, F->id]   ← identical

They diverge at step 2 and reconverge at step 8. Every row of the middle column and every row of the right column is a real sentential form of the grammar — there are just two legal itineraries through the same tree.

04

The Code, Explained

Building the tree — expand the frontier, one choice at a time

Reading a derivation off the finished tree

static List<Step> derivation(Grammar g, ParseTree root, boolean leftmost) {
  List<Step> steps = new ArrayList<>();
  List<ParseTree> frontier = new ArrayList<>(List.of(root));
  steps.add(new Step(symbols(frontier), null));   // form 0: just [S]

  while (true) {
    int i = pick(g, frontier, leftmost);       // index of leftmost/rightmost EXPANDED nonterminal
    if (i < 0) break;                          // frontier is all leaves — done
    ParseTree node = frontier.remove(i);
    frontier.addAll(i, node.children);          // splice the children in its place
    steps.add(new Step(symbols(frontier), node.production));
  }
  return steps;
}

The only difference between the two derivations is the direction pick scans the frontier. Everything else — which children, which production — was decided when the tree was built.

Why "expanded nonterminal," not just "nonterminal"?

In a finished tree every nonterminal node is expanded, so the two conditions are equivalent here. Stating it as "expanded" makes the same function correct on a partial tree too, and makes pick's logic line up exactly with build's frontier. See DECISIONS.md.

05

Limits — what this module cannot do yet

Can't do yet

  • Find the tree for a string. You supply the production choices; discovering them from the input is parsing (Modules 15+).
  • Handle a string with two trees — this module assumes exactly one. Module 6 is what happens when there are more.
  • Attach meaning to a node. The tree is pure structure; values, types, and evaluation come with attribute grammars (Module 37).
  • Cope with a grammar whose choices you got slightly wrong — build throws, it doesn't search or recover.

Can do

  • Build a parse tree from a grammar and a list of production choices.
  • Read the leftmost and the rightmost derivation off that one tree.
  • Show the two derivations use the identical multiset of productions.
  • Recover the string from the tree (terminalYield).
  • Render the tree as readable ASCII.
  • Demonstrate that when a grammar never puts two nonterminals in one form, the two derivation orders coincide exactly.

07

Brain Exercise

The anbn run shows leftmost and rightmost derivations that are byte-for-byte identical.

State the exact condition under which a grammar's leftmost and rightmost derivations of every string coincide. Then: for the expression grammar, is the map parse tree → leftmost derivation one-to-one? Is parse tree → string?

Answer

Coincidence condition: leftmost = rightmost for every string iff no sentential form reachable from the start symbol ever contains two or more nonterminals. Equivalently: every production's right-hand side contains at most one nonterminal (a "linear" grammar), and the start symbol is such. If a form ever has two nonterminals, "leftmost" and "rightmost" pick different ones and the sequences diverge — as they do for E + T in the expression grammar.

Tree → leftmost derivation: one-to-one (a bijection). Given the tree, the leftmost derivation is forced — at each step there is exactly one "leftmost expanded nonterminal." Run it backwards and each leftmost derivation reconstructs exactly one tree. This is why parsers target the leftmost (or rightmost) derivation: nailing it down is nailing down the tree.

Tree → string: many-to-one only if the grammar is ambiguous. For the unambiguous expression grammar, each string has one tree, so it's one-to-one here. Module 6 is precisely the case where it isn't.

08

There Are No Dumb Questions

If the tree is what matters, why does anyone talk about derivations at all?

Because a parser produces one incrementally, token by token, and the derivation is the running record of that process. A top-down parser builds a leftmost derivation as it reads left to right (Module 19); a bottom-up parser builds a rightmost derivation in reverse (Module 27). The derivation is the parser's play-by-play; the tree is the final score.

Is "leftmost" the same as pre-order traversal of the tree?

Close. A leftmost derivation expands nodes in the order a pre-order walk visits internal nodes. The sentential forms are the "frontier" of that walk at each moment. Rightmost corresponds to a right-to-left pre-order (visit node, then children right to left) — or equivalently, reverse of a left-to-right post-order.

The grammar has E -> E + T. Doesn't that recurse forever?

It would break a top-down parser — that's Module 16's whole topic. But this module doesn't parse; it applies productions you chose. The choice list [0, 1, ...] uses E -> E + T once and then E -> T, so the recursion bottoms out. Left recursion is a problem for a strategy, not for a grammar or its trees.

Why sort the production multiset before comparing?

Because the claim is "the two derivations use the same productions, regardless of order." Sorting by production index throws the order away so the comparison is exactly "same bag of rules?" — which is the thing being asserted. If we compared them in application order, they'd differ, and that difference is the point, not a bug.

Could a single tree have a derivation that's neither leftmost nor rightmost?

Yes — any order that expands each node after its parent is a valid derivation of the tree, and most trees have many. Leftmost and rightmost are just the two canonical ones: fully determined by the tree, easy to generate, and each in bijection with the tree. Parsers standardise on one so that "the parse" has a single well-defined meaning.

09

What's Next

Everything here assumed a string has one tree. Module 6 — Ambiguity & Disambiguation breaks that assumption: the grammar E -> E + E | E * E | id gives id + id * id two distinct parse trees — one meaning "(id + id) * id," one meaning "id + (id * id)." You'll build a detector that finds both, and then the standard rewrites (precedence tiers, associativity) that force a grammar back down to one tree per string — which is exactly the shape of the grammar you used today.
