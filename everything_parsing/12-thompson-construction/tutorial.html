Everything Parsing · Module 12 · Part II — Lexical Analysis

Thompson'sConstruction

Six tiny gadgets — one per regex node — snap together to build an ε-NFA for any regex. Each gadget has one entry and one exit, so they compose without friction, and the whole automaton has at most 2·|regex| states.

The pipeline advances

Module 3's regex tree → Thompson → an ε-NFA → (Module 11's removeEpsilon) → an ε-free NFA. Same language at every step, checked against the regex engine and Module 10's DFA. Module 13 adds the last arrow: → DFA.

01

The Big Analogy — snap-together track

Think of a model-railway set where every piece — straight, curve, Y-split, loop — has the exact same connector on each end. Because the connectors match, you can snap any piece to any other and the layout just works.

Thompson's gadgets are track pieces. A Char c is a straight with a turnstile that only opens for c. Concat is a coupling: snap one section's exit to the next's entry. Union is a Y-splitter that forks and rejoins. Star is a loop piece with a bypass siding.

Every piece has one entry connector and one exit connector — that's what makes them snap together in any order. You lay the track by walking the regex tree bottom-up: build the small pieces, snap them into bigger ones.

And the piece count is proportional to the regex: each character or operator adds a fixed, small number of connectors (states). Lay a regex of length L and you get a layout with at most 2L junctions.

02

What Happens, Step by Step

Recurse over the regex tree. Each call returns a fragment (start, end, transitions); one counter mints fresh state names q0, q1, ….

  1. ∅ → two fresh states, no transitions (accepts nothing).
  2. ε → s -ε-> e.
  3. Char c → s -c-> e.
  4. Concat(l, r) → build l, build r, add l.end -ε-> r.start. Fragment = (l.start, r.end). 0 new states.
  5. Union(l, r) → fresh s, e; s -ε-> l.start, s -ε-> r.start, l.end -ε-> e, r.end -ε-> e. +2 states.
  6. Star(x) → fresh s, e; s -ε-> x.start, s -ε-> e, x.end -ε-> x.start, x.end -ε-> e. +2 states.

The counter's final value is the state count. Emit states: / alphabet: / start: / accept: plus the transition lines, and hand the text to Module 11's Nfa.parse.

The Code, Explained

The recursion — one case per gadget

The bound, by structural induction

Claim: a fragment for a regex with k nodes has ≤ 2k states. Base: Char/ε/∅ have 1 node, 2 states — 2·1. Step: Concat of a+b nodes has 1 + a + b nodes and (≤2a) + (≤2b) + 0 states ≤ 2(a+b) < 2(1+a+b). Union/Star add 1 node and 2 states: (≤2a) + 2 = 2(a+1). Every case keeps states ≤ 2·nodes. ∎

Building the NFA — emit text, reuse the loader

StringBuilder sb = new StringBuilder("states:");
for (int i = 0; i < c.n; i++) sb.append(" q").append(i);
sb.append("\nalphabet:");  // collected from Char nodes
// ... start, accept, transition lines ...
return Nfa.parse(sb.toString());   // Module 11's tested loader

Limits — what this module cannot do yet

Can't do yet

  • Produce a DFA — the output is an ε-NFA (Module 13 flattens it).
  • Produce a minimal NFA — Thompson's is deliberately un-optimised (Module 14 minimises the DFA).
  • Handle regex features Module 3 doesn't have — ., classes, anchors, backreferences.
  • Match in guaranteed-DFA time — the ε-NFA simulation is O(states × input).
  • Report where a match is (submatches / capture groups).

Can do

  • Compile any Module-3 regex to an ε-NFA with 6 trivial gadget rules.
  • Guarantee ≤ 2·|regex| states, by structural induction.
  • Feed the result straight into Module 11's simulator and removeEpsilon.
  • Match every string the regex matches, verified against Module 3 and Module 10.
  • Report the exact state count for a regex without building the NFA.

Getting a blank or broken result?

State count exceeds 2·nodes — a gadget calls fresh() more than its budget. Concat must call it zero times.
The NFA rejects a string the regex matches — a gadget wired the wrong endpoint. Concat: l.end → r.start. Star loop: x.end → x.start.
(a*)* hangs — you're using a backtracking matcher. Nfa.accepts tracks a set and never backtracks.

07

Brain Exercise

Thompson's NFA is full of ε-transitions and ε-only states. Glushkov's construction (the "position automaton") produces an ε-free NFA with exactly |chars| + 1 states.

(1) So why is Thompson the one everyone learns and implements? (2) The Concat gadget adds 0 states via an ε-edge. Thompson's original paper merges l.end and r.start instead — also 0 states. Name a reason to prefer the ε-edge.

Answers

(1) Thompson is trivial: six cases, each a fixed handful of states and edges, no auxiliary computation. Glushkov needs nullable, first, last, and follow sets computed over the regex tree — correct, but more code and more to get wrong. Thompson also composes incrementally (append a node, extend the NFA), which matters for building regexes on the fly. The ε-transitions it leaves behind are removed for free by ε-closure. You reach for Glushkov only when NFA size genuinely matters.

(2) The ε-edge keeps every fragment self-contained: it still has its own distinct start and end, so a bottom-up construction can build fragments independently and stitch them later without renaming anyone's states. Merging l.end with r.start means one of them stops existing, which entangles the two fragments. (Production implementations often merge anyway, for the slightly smaller NFA — it's a real trade-off, not a mistake either way.)

08

There Are No Dumb Questions

Why all the ε-transitions? They look like clutter.

They're the wiring that lets gadgets snap together with one connector shape. Every ε-transition is erased for free by ε-closure (Module 11) or by the subset construction (Module 13). You're trading a temporarily bigger NFA for a construction that fits in six lines you can't get wrong.

a** — does the double star break anything?

No. It's Star(Star(Char a)) — two loop gadgets nested. It builds fine, has a few extra ε-states, and matches exactly a*. A backtracking regex engine would spin on a** against a long non-match; the set simulator here does not.

Is this how real regex engines work?

The good ones, yes. RE2, Go's regexp, grep, awk build an NFA (Thompson or a close relative) and simulate it — or lazily determinise it — in guaranteed linear time. PCRE, Perl, Python's re, JavaScript's RegExp use backtracking, which supports backreferences but can blow up exponentially ("catastrophic backtracking").

The bound is 2·|regex|. Can you do better?

Glushkov: |chars| + 1 states, ε-free. Antimirov's partial derivatives: similar. Follow automaton: also compact. All correct; all more involved. Thompson trades a factor of ~2 in size for being the simplest correct construction there is.

What sets the built NFA's alphabet?

Exactly the characters that appear in Char nodes of the regex. Nothing else — . ("any character") isn't a Module-3 node, and would have to be expanded to a union over Σ first (Module 3's Q&A covered that).

What's Next

You have regex → ε-NFA → ε-free NFA. Module 13 — Subset Construction adds the last arrow: → DFA. Each DFA state is a set of NFA states — "everywhere a clone could be" — computed by ε-closure and move. You'll prove the DFA accepts the same language, and exhibit the case where it explodes: the NFA for "the k-th symbol from the end is a" has k+1 states, its DFA 2ᵏ. Then Module 14 shrinks the DFA to its unique minimum, and the regex-to-matcher pipeline is complete and optimal.
