Everything Parsing · Module 04 · Part I — Foundations

Context-FreeGrammars

Formally, a grammar is the 4-tuple (N, Σ, P, S) — nonterminals, terminals, productions, start symbol — plus one relation, ⇒. That relation, applied over and over, generates the language. This module loads any such grammar as data and runs ⇒ until the strings come out, giving "well-formed" its real definition: there exists a derivation.

The whole idea in one line

S ⇒ a S b ⇒ a a S b b ⇒ a a b b — three applications of two rules. Change the rules you pick, get a different string. The set of every string you could ever reach this way, starting from S, is the language.

00

Prerequisites

  • a language is a set of strings
  • ⇒, ⇒*, sentential form, ε
  • reading a production out loud
  • toolchain

From Module 1: you recognized a language with an ad-hoc counter. That counter was secretly one specific grammar. This module makes the grammar explicit and general.

01

The Big Analogy — the rubber-stamp kit

You have a sheet of paper with a single empty box drawn on it, labelled S. Next to you: a small tray of rubber stamps. Each stamp carries a label and, when you press it onto a box with that label, it replaces the box with a short strip of ink. Some of that ink is finished text. Some of it is more empty boxes.

The S stamp comes in two faces. One prints a [S] b — a letter, a fresh box, a letter. The other prints nothing at all and the box just vanishes. You keep pressing stamps onto whatever empty boxes remain. When there are no boxes left, the page is done: it's a sentence of the language.

Press the first face twice, then the empty face: [S] → a[S]b → aa[S]bb → aabb. A different sequence of presses gives a different page. The language is every page the kit can ever produce. The kit has two stamps. The pages never run out.

02

What Happens, Step by Step

  1. Load the grammar. Strip # comments. Each line LHS -> ALT | ALT becomes one Production per alternative, in file order, numbered from 0. epsilon or an empty alternative → rhs = [].
  2. Classify symbols. Every LHS is a nonterminal. Every other symbol appearing in any RHS is a terminal. (Nothing is declared — having a rule is what makes you a nonterminal.)
  3. Start form is the one-element list [S].
  4. One derivation step: find the leftmost nonterminal at index i; pick one of its productions; replace form[i] with that production's rhs (splice).
  5. Repeat until no nonterminal remains. The result is one string of L(G). A different sequence of production choices is a different string.
  6. Enumerate the language: breadth-first over all choice sequences, discarding any form whose terminal count already exceeds the length bound.
  7. Decide membership (w ∈ L(G)?): the same breadth-first search, targeting w, bounded by |w| terminals.

The state, drawn

One leftmost derivation of a a b b

choices:  0            0              1
          │            │              │
  [ S ]   ▼            ▼              ▼
  ───►  [ a S b ]  ───►  [ a a S b b ]  ───►  [ a a b b ]
        prod 0         prod 0          prod 1
        S → a S b      S → a S b       S → ε
        (leftmost S is the only S each time)          no nonterminals left — done

Enumeration is a breadth-first frontier, ordered by terminal count

terminals: 0        2        4          6              8
           │        │        │          │              │
  frontier [S]  →  a[S]b  →  aa[S]bb  →  aaa[S]bbb  →   aaaa[S]bbbb  (> bound 6: dropped)
            │        │         │            │
   emit:   (S→ε)    (S→ε)     (S→ε)        (S→ε)
            ε        ab        aabb         aaabbb

  language ≤ 6  =  { ε, ab, aabb, aaabbb }        raise the bound → one more, always

The frontier only ever moves right (terminal count strictly increases with every S → a S b). That is why the search terminates, and it is the same fact that makes the membership bound sound — see the Brain Exercise.

04

The Code, Explained

A derivation step is a list splice

This is the entire derivation relation ⇒. Everything else — enumeration, membership — is a loop that calls substitute and decides which i and which rhs.

The bounded search, and why its bound is honest

// derives(g, target): breadth-first, bounded by the target's terminal length
int bound = target.size();
while (!queue.isEmpty() && budget-- > 0) {
  List<String> form = queue.poll();
  int i = leftmostNonterminal(g, form);
  if (i < 0) {                                // fully terminal
    if (form.equals(target)) return /* DERIVABLE, with depth */;
    continue;
  }
  for (Grammar.Production p : g.productionsFor(form.get(i))) {
    List<String> next = substitute(form, i, p.rhs());
    if (terminalCount(g, next) > bound) continue;   // ← the prune
    if (!depth.containsKey(key(next))) { depth.put(key(next), d + 1); queue.add(next); }
  }
}
Why terminalCount(next) > bound is safe to prune

A terminal symbol is never the left-hand side of any production — so no derivation step can ever remove a terminal. Every intermediate form on the way to w therefore has at most |w| terminals. Dropping forms with more than that cannot drop a form that leads to w. When the queue empties, "NOT DERIVABLE" is a proof, not a time-out.

Loading a rule: the | is pure sugar

for (String alt : r[1].split("\\|")) {          // "a S b | epsilon" → ["a S b ", " epsilon"]
  alt = alt.strip();
  List<String> syms = new ArrayList<>();
  if (!alt.isEmpty() && !alt.equals("epsilon"))
    for (String s : alt.split("\\s+")) syms.add(s);
  prods.add(new Production(prods.size(), lhs, syms));   // one Production per alternative
}

S -> a S b | epsilon becomes productions 0 and 1. Downstream algorithms select "a production," so the alternative is the right unit. See DECISIONS.md #2.

05

Limits — what this module cannot do yet

Can't do yet

  • Decide membership efficiently — the search is exponential in the worst case (see Brain Exercise).
  • Handle a left-recursive rule like E → E + T without the search exploding — Module 23 fixes the grammar; Modules 19+ parse it directly.
  • Build a parse tree. We produce strings, and a flat list of sentential forms — no structure is retained.
  • Tell you which derivation is "the right one" when a grammar is ambiguous (Module 6).
  • Read an input left-to-right. It only generates outward from S.

Can do

  • Represent any context-free grammar as data, loaded from a file.
  • Perform a specified leftmost derivation and show every sentential form.
  • Enumerate a language up to a length bound, in canonical order.
  • Prove a language is infinite by construction.
  • Decide membership for short strings, with a sound "not in the language" answer.
  • Serve as the substrate every later Track-1 module runs on — Grammar and substitute don't change again.

Getting a blank or broken result?

rule has no '->' — a non-comment line that isn't a rule. Every line is LHS -> ..., %start X, blank, or #.
Enumeration prints nothing — every recursive rule needs a non-recursive alternative, or nothing ever finishes. S -> a S b alone (no | epsilon) generates an empty language.
derives says NOT DERIVABLE for something you think is in the language — recheck by hand; if it really is derivable, your grammar has a unit or epsilon cycle inflating the search past the safety cap. Modules 23 and 23 remove those.

07

Brain Exercise

Two parts.

(1) Section 04 claimed the prune "drop any form with more than |w| terminals" never loses a form that leads to w. Write that argument out in two sentences.

(2) Give a grammar whose language is finite and tiny — fewer than ten strings — for which enumerate nonetheless approaches the MAX_FORMS cap as you raise the bound. What is the search actually drowning in?

Work both out first.

(1) No terminal symbol is ever a left-hand side, so no derivation step can delete a terminal; a form's terminal count only ever stays the same or grows. Therefore every sentential form on any path from S to w has ≤ |w| terminals, and pruning the forms with more than that removes only forms that could never have reached w.

(2) S -> S S | a | epsilon. The language is just {ε, a, aa, aaa, …} — effectively a*, and if you also want it finite, drop the recursion base: S -> A A A A A A, A -> a | a gives the single string aaaaaa, yet S -> S S | a has Catalan-many distinct sentential forms of a given terminal count — a(SS), (SS)a, (S(SS)), … — all producing the same handful of strings. The search is drowning in parse-tree shapes. Generation explores one branch per tree; a real parser (Module 19 on) reads w once and never forks. That difference — same yes/no answer, exponential vs. linear — is the entire reason the rest of Track 1 exists.

08

There Are No Dumb Questions

Is a grammar just a fancy regular expression?

Other way around: a regular expression is a grammar with recursion restricted — a nonterminal may only refer to itself at the very end of a rule (right-linear). Every RE can be written as a CFG. Not every CFG can be written as an RE: S → a S b | ε can't, because matching aⁿbⁿ needs unbounded memory of "how many as." Module 7 proves exactly this with the pumping lemma.

Why always expand the leftmost nonterminal? Couldn't I expand any of them?

You could, and the finished string — and its parse tree — would be identical. Fixing "leftmost" gives each parse tree exactly one derivation, so enumerate doesn't emit aabb five times via five reorderings of the same three choices. Which canonical order you pick (leftmost vs. rightmost) turns out to be the fork between top-down and bottom-up parsing — that's Module 5.

derives only "searched forms with ≤ N terminals." Isn't a bounded search just giving up early?

Not here. Because terminals can never disappear (Brain Exercise part 1), every form that could possibly reach an N-terminal target has ≤ N terminals. Searching all of those and finding nothing is a complete proof that the string is not in the language. The MAX_FORMS cap is a give-up — but it only triggers on grammars with cycles, which the course teaches you to remove.

The grammar file has epsilon in it, but you say there's no epsilon symbol. Which is it?

epsilon is a keyword in the file format meaning "this alternative's right-hand side is empty." After loading, that production has rhs = [] and the alphabet Σ never contains a symbol called epsilon. Writing S → a epsilon is rejected at load time because an empty thing concatenated with a is just a — the epsilon can only be a mistake.

This breadth-first search reads like a parser already. Why are there 20 more modules?

This is recognition by generating the whole language until the target shows up (or the bound proves it won't). It's correct and it's exponential. A parser reads the input string left to right, uses the next token to decide which rule applies, and never explores a branch that the input already rules out — linear time. Modules 19–36 are the different ways to make that decision reliably.

What's Next

Your derivation engine produces a flat sequence of sentential forms and throws the structure away. Module 5 — Derivations, Parse Trees, Leftmost/Rightmost keeps the structure: every derivation step becomes a parent–child link, so the output is a tree. You'll prove that the leftmost derivation you built here and the rightmost derivation you haven't are two readings of the same tree — and that the tree, not the string, is what every parser is really after.
