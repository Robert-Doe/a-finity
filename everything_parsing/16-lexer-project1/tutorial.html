The LexicalAnalyzer

A complete, data-driven scanner. Feed it a token-spec file; it compiles every pattern into one combined DFA whose states are tagged with the winning token, then makes a single left-to-right pass — maximal munch, priority, whitespace-skipping, exact error columns, and the load-time check that no token matches the empty string.

This is the whole front end of a compiler's front end

8 spec lines → 1 DFA of 43 states. let.x=12.in.x → KW_LET ID ASSIGN NUM KW_IN ID. inlet → one ID. (a|b)* as a token → rejected: epsilon IS NOOOOOT A TOKEN.

The Big Analogy — one receptionist who knows every form

The naive design has eight specialists — a keyword clerk, an identifier clerk, a number clerk — and you'd have to try your document at each desk.

Instead: one receptionist who has memorised every document type. They read your paper character by character, and at every moment they know: "if this ended right now, it would be a purchase order — or an invoice." They keep reading as long as it's still becoming something valid. When they can't read further, they stamp it with the highest-priority category it currently qualifies as, tear off that much paper, and start reading the rest.

Blank separator sheets between documents? The receptionist recognises them and quietly bins them (whitespace, skipped). A character that fits no document type? They stop and tell you exactly which character, at which position (lexical error).

And before you even hand them the rulebook: if one rule says "a document can be zero pages long," they refuse the rulebook. A zero-length document would let them "recognise" one at every position without moving — forever. Epsilon is not a token.

02

What Happens, Step by Step

LOAD:

  1. Parse the spec: NAME regex per line, priority = file order; %skip NAME lines mark trivia.
  2. Reject nullable patterns. For each pattern, build its Thompson NFA; if εClosure({start}) ∩ accept ≠ ∅, the pattern matches "" → error, *"epsilon IS NOOOOOT A TOKEN"*.
  3. Combine. Fresh START; START -ε-> ruleᵢ.start for each pattern; tag each pattern's accept state with its rule index.
  4. Determinize (Module 13). For each combined-DFA state, its token = the smallest rule index among the tagged NFA states in its subset.

SCAN (from pos = 0):

  1. state = dfa.start; lastPos = -1.
  2. Step the DFA over input[pos..]; each time it enters a tagged state, record (lastPos = i+1, lastRule = tag). Stop when it can't advance.
  3. If lastPos ≤ pos → LexicalError(pos, input[pos]).
  4. Emit token (rules[lastRule].name, input[pos..lastPos]) unless it's a %skip kind. Set pos = lastPos.

The combined automaton

              ├─ε─▶ [ NFA for "in" ]       ──accept──▶ tag 1  (KW_IN)
   START ─────┼─ε─▶ [ NFA for ID regex ]   ──accept──▶ tag 2  (ID)
              ├─ε─▶ [ NFA for NUM regex ]  ──accept──▶ tag 3  (NUM)
              ├─ε─▶ [ NFA for "<=" ]        ──accept──▶ tag 4  (LE)
              └─ ...                                 (LT=5, ASSIGN=6, WS=7)

   determinize  →  one DFA.  each state's tag = MIN rule index it can accept.
                             tag 0 < tag 2  →  "let" beats "ID" on a length tie.

Scanning let.x

  pos 0:  state D0
    'l' → Dp   (ID-live)            no accept yet
    'e' → Dq   (ID-live)            accept ID @2 ... wait "le" is a valid ID → lastPos=2, tag=2
    't' → Dr   (KW_LET accept + ID accept)  →  tag = min(0, 2) = 0   → lastPos=3, tag=0
    '.' → not reachable from Dr in any pattern except WS... 'l/e/t/i/n/x/y'  → '.' stuck
  emit  KW_LET "let" @0            (tag 0 beat tag 2 at length 3)
  pos = 3

  pos 3:  '.' → WS accept @4, tag 7   → emit nothing (WS is %skip)
  pos 4:  'x' → ID accept @5, tag 2   → emit  ID "x" @4

The Code, Explained

Tagging the combined DFA

// each combined-DFA state -> the highest-priority (lowest index) token it accepts
for (var e : legend.entrySet()) {        // legend: DFA state name -> its subset of NFA states
  int best = Integer.MAX_VALUE;
  for (String nfaState : e.getValue()) {
    Integer ri = acceptRule.get(nfaState);   // null unless this NFA state is a tagged accept
    if (ri != null && ri < best) best = ri;
  }
  if (best != Integer.MAX_VALUE) stateToken.put(e.getKey(), best);
}

The scan — maximal munch over the combined DFA

Crazy detail — "epsilon IS NOOOOOT A TOKEN"

That exact, capitalised, over-exclaimed phrase is from ASU CSE 340's Project 1 autograder. It's shouted because a nullable token pattern is the single most common way a student's scanner hangs: every position "matches" length 0, pos never advances, infinite loop. Catching it at load — εClosure({start}) ∩ accept ≠ ∅ on the pattern's NFA — turns an infinite loop into one clear error. This course keeps the phrase.

05

Limits — what this module cannot do yet

Can't do yet

  • Minimize the combined DFA — naive minimization merges different token tags (needs tag-aware partitioning).
  • Recover from a lexical error and keep going (Module 17).
  • Handle regex features Module 3 lacks — character classes, negation, escapes — so no [a-z], no //.* comments.
  • The reserved-word trick, nested comments, string escapes (Module 18).
  • Attach line/column ranges to tokens — only a single start position.

Can do

  • Build a working lexer entirely from a text spec file.
  • Compile all patterns into one tagged DFA and scan in O(input).
  • Apply maximal munch and priority together, in a single pass.
  • Skip whitespace/trivia while keeping source positions correct.
  • Report a lexical error with an exact character position.
  • Reject a nullable token pattern before scanning ever starts.

Getting a blank or broken result?

token 'X' can match the empty string — a pattern is nullable (a?, (a|b)*, ()). Every token must consume ≥ 1 character.
'(' has nothing to apply to while loading — a token literal is a regex metacharacter, and Module 3's regex has no escaping.
A keyword lexes as ID — ID is declared before the keyword. Keywords go first.
Positions drift after whitespace — pos must advance by the lexeme length, skipped tokens included.

07

Brain Exercise

(1) The combined DFA has 43 un-minimized states. Minimize it with the standard {F} | {Q\F} initial partition — what breaks? What's the fix? (2) Our spec uses "priority = file order." flex uses "longest match, then earliest rule." Same thing? Give an input where they'd differ, or argue they can't.

Answers

(1) Standard minimization merges accepting states that behave identically on future input — so a state that accepts KW_LET and a state that accepts ID could merge if their transitions match, and the merged state can no longer say which token. The fix is tag-aware minimization: the initial partition has one block per token tag (plus one for non-accepting), so no split ever puts two different token kinds together. flex and re2c do exactly this, then compress the tables.

(2) Same thing, for token boundaries. Both say: the token is the longest prefix any pattern matches (maximal munch); on a length tie, the earliest-declared pattern. Where "leftmost-longest," POSIX, and backtracking semantics differ is in submatch / capture-group resolution — which a tokenizer doesn't use. For deciding where one token ends and the next begins, every serious lexer agrees.

08

There Are No Dumb Questions

Why one combined DFA instead of just trying each pattern's DFA?

Speed and standard practice. Trying each pattern is O(rules × input) per token; the combined DFA is O(input) total, one step per character, regardless of how many token kinds you have. lex, flex, re2c all generate a single combined (and minimized, and table-compressed) DFA.

Why is CSE 340 so loud about "epsilon IS NOOOOOT A TOKEN"?

Because a nullable token pattern is the #1 cause of a Project 1 scanner hanging: every position "matches" length zero, the cursor never moves, infinite loop, autograder timeout. Detecting it at load and shouting turns a silent hang into a one-line fix.

How do real lexers do //-to-end-of-line or /* */ comments?

With regex features Module 3 doesn't have — character-class negation (//[^\n]*) — or with lexer modes: on seeing /*, switch to a "in comment" state that consumes everything until */. Nested comments need a counter, which is technically beyond regular — a small hand-coded exception. Module 18 covers these.

43 states for 8 tiny patterns — isn't that bloated?

Yes. Un-minimized union DFAs carry all the ε-scaffolding from Thompson's construction. Tag-aware minimization (Brain Exercise) would cut it to maybe a dozen, and table compression shrinks it further. This module leaves it un-minimized to keep the union-and-tag construction in focus.

Can two different specs produce the same lexer?

Yes — reorder rules that can never tie, rename tokens, or write equivalent regexes (Module 14 can prove two regexes equivalent). What's observable is the token stream a given input produces; many specs yield the identical stream.
