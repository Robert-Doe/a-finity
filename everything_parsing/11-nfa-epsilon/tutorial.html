Everything Parsing · Module 11 · Part II — Lexical Analysis

NFA andε-NFA

Loosen the DFA's rules: δ(q, a) may be a set of states — zero, one, or many — and ε-transitions move without consuming input. It's far easier to build. And it buys exactly zero extra power: removeEpsilon() proves it by construction.

Nondeterminism = explore every branch at once

The NFA for (a|b)*abb takes S -a-> S and S -a-> S1 on the same character — one branch keeps looping, the other bets the final abb starts here. Accept if any branch is in an accepting state when the input ends.

01

The Big Analogy — the detective who clones themselves

A DFA detective works one thread: this clue leads to that room, which leads to the next. One line of investigation.

An NFA detective clones themselves at every fork. Two doors marked "a"? One clone takes each. A clone that hits a dead end simply vanishes. The case is solved — the string accepted — if any clone is standing in the culprit's room (an accepting state) when the evidence runs out (the input ends).

An ε-transition is an unlocked connecting door: a clone can step through it for free, without spending a clue. Before you even present the first piece of evidence, clones spill through every unlocked door — that's the ε-closure of the start.

"No extra power" means: you could instead hire one very organised detective who, at every step, writes down the complete list of rooms a clone could be in. That list is a single DFA state. Same conclusions, one investigator. (Module 13 hires them.)

02

What Happens, Step by Step

  1. ε-closure of a set: worklist search — repeatedly add any state one ε-step away, until nothing new.
  2. Start: cur = εClosure({start}).
  3. Per symbol a: moved = ⋃ δ(s, a) for every s ∈ cur; then cur = εClosure(moved). If cur = ∅, every branch is dead — reject now.
  4. Accept iff cur ∩ F ≠ ∅ at the end.
  5. removeEpsilon(): for each state q, new δ'(q, a) = εClosure( δ( εClosure(q), a ) ), and q becomes accepting iff εClosure(q) already contained an accepting state. Result: an ε-free NFA, same language.

The Code, Explained

ε-closure — a worklist reachability search

The simulator — a set, not a state

boolean accepts(List<String> input) {
  Set<String> cur = epsilonClosure(Set.of(start));
  for (String sym : input) {
    Set<String> moved = new LinkedHashSet<>();
    for (String s : cur) moved.addAll(move(s, sym));   // every branch, in lockstep
    cur = epsilonClosure(moved);
    if (cur.isEmpty()) return false;               // all branches dead
  }
  return !intersect(cur, accept).isEmpty();
}

removeEpsilon — the "no power" proof, in one method

for (String q : states) {
  Set<String> cq = epsilonClosure(Set.of(q));
  if (!intersect(cq, accept).isEmpty()) nAccept.add(q);   // q accepting if its closure hits F
  for (String a : alphabet) {
    Set<String> moved = new LinkedHashSet<>();
    for (String p : cq) moved.addAll(move(p, a));
    Set<String> target = epsilonClosure(moved);            // δ'(q,a) = εClose(δ(εClose(q), a))
    if (!target.isEmpty()) nd.get(q).put(a, target);
  }
}
Crazy detail — "explore all branches" is not "try one, backtrack"

A backtracking matcher tries one path, and on failure rewinds and tries another — worst case, exponential (the infamous "catastrophic regex backtracking"). The set simulator here explores all paths simultaneously, one lockstep per character: at most |states| states in the set, so O(|states| × |input|), always. Same acceptance decision, no blow-up. That's why grep and RE2 use automaton simulation, not backtracking.

05

Limits — what this module cannot do yet

Can't do yet

  • Build an NFA from a regex — the fixtures are hand-written (Module 12: Thompson's construction).
  • Remove the nondeterminism — removeEpsilon() leaves an NFA, still multi-valued (Module 13: subset construction).
  • Minimise anything (Module 14).
  • Beat a regex on any language — still exactly the regular languages.
  • Run in guaranteed-DFA time — the set can be up to |states| big each step.

Can do

  • Simulate an NFA with branching and ε-moves by tracking the state set.
  • Compute ε-closure of any state set.
  • Remove all ε-transitions, producing an equivalent ε-free NFA.
  • Show the language is unchanged by ε-removal, and matches the DFA and the regex.
  • Trace the state set at every step of a run.

07

Brain Exercise

(1) The NFA for (a|b)*abb has 4 states; the DFA (Module 10) also has 4. Coincidence? What's the worst case when you convert an k-state NFA to a DFA?

(2) ε-closure runs before the first symbol and after each one. What breaks if you skip the "before the first symbol" run?

Answers

(1) Coincidence-ish. The subset construction (Module 13) can produce up to 2ᵏ DFA states from a k-state NFA, because a DFA state is a set of NFA states. The classic blow-up: the NFA for "the k-th symbol from the end is a" has k + 1 states; its minimal DFA has 2ᵏ — it must remember the last k symbols. (a|b)*abb stays small only because few of its 2⁴ subsets are reachable.

(2) Any accepting path that begins with ε-moves is lost. Concretely: (a|b)* would stop accepting the empty string, because F is only reachable from the start I via ε — and without the initial closure the run would start at {I}, see no input, and check {I} ∩ F = ∅ → wrongly reject.

08

There Are No Dumb Questions

"Nondeterministic" — does the machine flip a coin?

No. It's a mathematical term meaning the transition relation isn't a function — a state can have several successors on one symbol. The machine accepts if some sequence of choices leads to an accepting state. Real implementations don't guess; they either simulate all branches at once (a set, as here) or backtrack through them.

If an NFA has exactly the power of a DFA, why ever build one?

Because building an NFA from a regex is trivial and compositional — Module 12 does it with one small gadget per regex node. Building a DFA for the same regex directly is painful and the DFA can be exponentially bigger. Standard pipeline: regex → NFA (easy) → DFA (mechanical, Module 13) → minimal DFA (Module 14).

The ε-NFA has states (U, W) that only do ε-transitions. Wasteful?

They're scaffolding. Thompson's construction adds a couple of ε-only states per operator so every gadget has a single entry and single exit and they compose uniformly. removeEpsilon() here, then minimisation in Module 14, clean them out. The regularity is worth the temporary bloat.

Can an NFA be smaller than the minimal DFA for the same language?

Yes — sometimes exponentially smaller (the "k-th from the end" example). The catch: minimising an NFA is PSPACE-complete, while minimising a DFA is polynomial (Module 14). So NFAs are compact but hard to optimise; DFAs are bigger but you can find the smallest one efficiently.

The trace shows the state set can shrink. When it hits {}, is that a bug?

No — it means every branch has died, so no continuation can accept, and the string is rejected. accepts returns false immediately in that case. A non-empty final set that misses F is also a reject, just without the early-out.
